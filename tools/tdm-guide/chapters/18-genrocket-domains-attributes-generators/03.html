18.6 Generators: the recipe for each value

From docs A generator creates synthetic data (or queries existing data) for one attribute. Every attribute needs one. GenRocket advertises over 765 generators (a growing number), grouped by purpose and, for many countries, by country. Generators produce raw values only; receivers format them (receivers and scenarios chapter).

18.6.1 How a generator gets assigned automatically

You rarely pick generators from scratch. For each new or imported attribute GenRocket tries these steps in order, according to the "How are Generators Assigned" page:

  1. Is there a matching Project generator tag? If yes, use it.
  2. Otherwise, a matching Organization generator tag?
  3. Otherwise, an intelligent guess from the domain name, attribute name, the project's industry type and usage patterns of other users. If Enforce Type/Limit is on, the column's type is considered too (a date column gets FlexibleDateRangeGen, a uniqueidentifier gets UUIDGen).
  4. If nothing fits, SimplePatternGen, which builds a value like name1, name2, name3 from the attribute name and the row's id.
Treat SimplePatternGen as a to-do marker

It generates values like street1, which are unique but not realistic. When you see it on an attribute, the tool could not guess; pick a better generator. The Project Version status report flags attributes without a generator.

18.6.2 Replacing a generator on one attribute

  1. Open the attribute and use the Quick Generator Replacement menu below the generator.

    Typing part of a name filters the list (typing "town" offers BulgariaTownGen and UKTownGen).

  2. Pick the generator and click Replace, then set its parameters and click Save Generator.

    What you should see: the new generator's name and parameters, and a fresh preview. Not sure of the name? Use Remove Generator and the Add a Generator dialog, which has categories and a search box.

18.6.3 Assigning one generator to many attributes

If first_name and last_name both need NameGen, do it in one go through the gear icon above the attribute list.

  1. Click the gear icon (Browse and Manage Attributes) and tick the attributes.

    Selected rows turn blue.

  2. Type the generator name in Select Generator, click Set Generator and confirm with Yes.

    The dialog warns that existing generators on those attributes will be replaced.

  1. Click Modify Generator Parameters to set a parameter for several attributes together.

    Here you can give firstName the value firstName in nameType and lastName the value lastName, each in its own row, or tick rows and set a shared parameter such as sortOrder.

The Generator Tuning Wizard (step 3 of the XTS wizard) does the same across the whole project version, with statistics on how well generators match attributes. Copying a configured generator to other attributes is possible too: Simple Copy to chosen attributes (up to 20 per bucket; it replaces the target's generator) and Pattern Copy to all attributes whose names follow a pattern.

18.6.4 Generator tags: steering the automatic choice

From docs A generator tag is a rule "if an attribute's name matches this text, assign this generator". Each has a value, a match type (starts with, ends with, contains or matches) and an optional ignore-case flag. Project-level tags apply to all versions of a project; organisation-level tags apply everywhere. The page's example: every attribute named like firstName in a Canadian project should get CanadaNameGen. Tags live in the Generator Tags tab of the Management pane (project) or the Organization menu.

To see which generators GenRocket thinks fit an attribute, click the small icon beside it in the attribute list. A ranked list appears (in the vendor's example NameGen 84%, AustraliaNameGen 5%, and so on); the top one is the default, and a tag icon lets you promote another.

18.6.6 Seeding: repeatable randomness

If two runs of a "random" generator give different numbers, test failures cannot be reproduced. A seed fixes this: the docs show a RandomGen for numbers 1 to 25 giving a new set every run when the seed is empty, but the same set whenever the seed is 1; a different seed (2) gives a different, but also repeatable, set. A seed can be set on an attribute's generator or through the domain's seed variable (button Global Seed applies it to the whole domain).

18.6.7 Linked generators

One attribute can hold several generators in a row (gen1, gen2...). They run left to right, a generator may use any generator to its left, and the last one gives the value. The docs' example builds a full name in a single fullName attribute: NameGen, AlphabetGen (middle initial), NameGen (last name), then ConcatGen joining the three. Without linking you would need four attributes and would have to hide three of them with Visible turned off.

18.6.8 ReferenceGen and ProxyReferenceGen: how a child finds its parent key

This pair is the mechanism behind foreign keys, and it confuses everyone once. The docs explain it as follows.

ProxyReferenceGen (domain level)

A placeholder. Because a template domain cannot see another domain, the foreign-key attribute holds this generator, whose only parameter is startRange (default 1000). It marks "a parent's key goes here".

Assigned automatically when you import with DDL or XTS and the column has a foreign key.

ReferenceGen (scenario level)

The real thing. When a scenario is created and the parent relationship exists, GenRocket swaps the proxy for ReferenceGen. Its one parameter reference points at the parent's primary attribute, such as #{AddressScenario.User.id}.

It can also be set up manually, as in the docs' "User and Address" example.

It explains why the project version status report asks for "foreign key attributes that do not have the ProxyReferenceGen". If the proxy is missing, the child will not find its parent when a scenario is made, and the reference value will not be filled in. The referenced attribute is the parent's primary attribute; if another column should be the target, tick its Primary checkbox.

18.6.9 Enforcing data type and size

A generator does not know that first_name is varchar(5) unless you tell it. From docs The Enforce Type/Limit option makes the generator keep values within the attribute's Type and Size. It is on automatically for generators assigned by a DDL or XTS import, can be enabled for a whole project version when you create it, and can be set manually per generator. The docs list integer limits it applies, for example 127 for tinyint, 32767 for smallint and 2147483647 for int.

  1. Open the attribute, set Type (for example varchar) and Size (for example 5) and save.

    These tell GenRocket the limits.

  2. Tick Enforce Type/Limit in the generator section and save the generator.

    What you should see: the preview now shows names of at most five characters.

18.6.10 Primary keys after the current maximum

When you insert into a table that already holds rows, new keys must not collide with old ones. The docs' recipe links two generators in the id attribute. gen1 is QueryOnceGen with resourceName pointing at the JDBC resource, query = select max(id) + 1 from <tableName> and a sampleValue (5001 in the example) used for previews. gen2 is RangeGen whose startRange references gen1.

The General FAQ adds a second pattern for the parent side: write the parent's ids to a delimited file as you insert, then read them back with ListCSVGen at scenario level (the FAQ says "in the Parent Domain"), so the keys match.

18.8 Common mistakes and gotchas

Watch for these
  • Expecting a DDL import to set relationships. It does not. Run the Domain Referencing Wizard.
  • Giving a table several parents. Use one parent and mark describing tables as siblings.
  • Referencing an attribute below the current one. The value is empty. Reorder first.
  • Leaving SimplePatternGen in place. It means no better guess was found.
  • Forgetting Enforce Type/Limit. Values may not fit the target column.
  • Forgetting that a new domain's loopCount is 1. A first run gives one row.
  • Using ListGen for large lists. It supports up to 15 values. The docs recommend ListCSVV2Gen or another file-based list generator for more. ListCSVGen loads the whole file into memory.
  • Exhausted unique values. RandomGen with a small range and uniqueLimit 1 stops with "Exhausted attempts to find the next valid random value" when the loop count is too high (the page's own example is a range of 1 to 20, a limit of 1 and 20 rows). Widen the range, raise the limit or lower the row count.

18.9 Recap

Key points
  • A domain is a table (template), an attribute is a column, and each attribute needs a generator.
  • Create domains by hand, with Scratch Pad, from DDL, or from a database with XTS. Imports do not set relationships or receivers.
  • Each domain has three variables: id, loopCount and seed.
  • One parent, many siblings. Parents generate first, so child foreign keys always find a parent.
  • ProxyReferenceGen is the domain-level placeholder; ReferenceGen is the scenario-level real reference.
  • GenRocket assigns generators by tags, then by guess, then SimplePatternGen. Replace them one at a time or in groups.
  • Seeds make random data repeatable; linked generators build complex values; Enforce Type/Limit keeps values inside column limits.
