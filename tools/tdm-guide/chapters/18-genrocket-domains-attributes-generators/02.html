18.3 Relationships: parent, child and sibling

Real tables point at each other: ORDERS.customer_id is a foreign key to CUSTOMERS (data basics chapter). If you generate 50 customers and 80 orders with random customer numbers, some orders will point at customers that do not exist, which breaks referential integrity. GenRocket's answer is to generate data in order, from parent to child, so a child can only pick a key a parent has already made.

From docs The documentation says GenRocket "generates synthetic data with full referential integrity" because every domain has an id or primary attribute, and children refer to the parent's primary attribute. It also says GenRocket looks at relationships differently from a database. A database table can have several foreign keys. A GenRocket domain may have only one parent but many siblings, because generating sequentially along several parents would produce "a large amount of unnecessary data".

TermMeaningRule of thumb from the docsShopSphere
ParentThe domain whose rows are created first and which children point toA real relationship between two tables, such as department and userCUSTOMERS for ORDERS; ORDERS for ORDER_ITEMS
ChildA domain that refers to its single parent's primary attributeExactly one parentORDERS, ORDER_ITEMS
SiblingA domain that only "describes" another, used for lookupsIf the table is an adjective of another (role is an adjective of user), mark it a siblingPRODUCTS describes an item: a sibling of ORDER_ITEMS

The scenario page adds a vocabulary pair: the primary domain is the one a scenario is created for, and the root domain is the first parent up the chain. For an ORDER_ITEMS scenario, ORDER_ITEMS is primary and CUSTOMERS is root, so the scenario creates customers, then orders, then items, and every key matches.

Why it matters

Valid foreign keys are the reason a test can load generated data into a real database and not see constraint errors. The same guarantee is what the generation concepts chapter asked for in principle (parents before children); GenRocket builds it into the domain model.

18.3.1 Setting a parent or sibling by hand

  1. Open the child domain's dashboard and click the Relationship tab.

    The relationship is stored on the child.

  2. Click Add Referential Parent and tick the parent's radio button, then Save.

    Radio buttons enforce the one-parent rule.

  1. For a lookup table, click Add Referential Sibling, tick one or more domains, and add them to the scenarios you want.

    What you should see: the Relationship tab draws a small diagram of the parent, the child and its siblings. If scenarios already exist, you are asked which scenarios should receive the new relationship.

18.3.2 The Domain Referencing Wizard

After importing many tables, setting parents one by one is tedious. The wizard shows every domain with radio buttons for parent and checkboxes for siblings, and a diagram that updates as you click. It opens from the Project Versions pane or from step 2 of the XTS wizard.

  1. Select a domain on the left.

    Its possible parents appear in the middle pane.

  2. Click a parent's radio button.

    Siblings are ticked automatically for the other domains, and the domain is marked Reviewed because you changed it.

  3. If a domain is already right, click Mark as Reviewed.

    This is how you track progress when hundreds of tables exist.

    What you should see: the progress pie fills as domains are reviewed. In the XTS wizard, finish by clicking Mark Completed for step 2.

18.4 Domain variables, loopCount and categories

From docs A domain variable is an instance variable of a domain, named global.DomainName.variableName. Generator parameters throughout the project can refer to it, and changing the value instantly changes everything that references it. Three exist by default:

VariableControlsDefaultExample from the docs
global.X.idThe start of the id attribute. The id attribute's RangeGen reads it as startRange1Set to 100: ids run 100, 101, 102...
global.X.loopCountHow many rows the domain generates1Set to 10,000: ten thousand rows
global.X.seedThe seed for random generators1Same seed in two domains gives the same random numbers in both

You can add your own, such as global.User.startDate. Defaults cannot be deleted.

18.4.1 Changing how many rows

The docs describe three levels at which the row count can be set, from broad to narrow: the domain (template) level, which applies everywhere; the test data case level, which they recommend as the most flexible because different tests can have different counts; and the scenario level, for special cases. This chapter changes it at the domain level.

  1. Open the domain and find the loopCount variable in Domain Variables.

    It starts at 1, which is why a first run produces a single row.

  2. Click its pencil icon, type the new value and click Save.

    What you should see: the Value column changes (in the vendor example, from 1 to 25).

For many domains at once, the Global Editing menu has an "Edit Domains LoopCount" screen with checkboxes. One quirk: if a domain's first generator is a ListGen with setLoop set to true, the list length overrides the loop count and you cannot edit it from the scenario.

18.4.2 Domain categories

When a version has dozens of domains, group them: open a domain, click Categorize, create a category and save. Then filter the Domains pane by category or use Advanced Search. The same categorising works for scenarios, scenario chains and chain sets.

18.5 Attributes: the columns

From docs An attribute defines a characteristic of a domain, and a domain needs attributes for any data to exist. Importing creates them from the schema; otherwise you add them by hand. Every new domain starts with an id attribute that produces a unique number per row.

Click an attribute to open the Attribute Dashboard. The top half holds the attribute's own parameters; the bottom half holds its generators.

Attribute parameterMeaning (docs wording, shortened)
Name / Original NameName is the camel-case name shown in the web platform. Original Name is the real column name as imported, and is what appears in output
% Null and Null ValueThe percentage of rows that get a null (for negative tests) and what "null" looks like

VisibleIf false, receivers do not see the attribute (useful for helper attributes)
PrimaryMarks the key that children reference (a key icon appears)
Type, Size, Required, Unique, Table ReferenceImported from DDL or XTS: the column's declared type, length, null-ability, uniqueness and foreign-key target

Name versus original name

For ShopSphere's customer_id column the attribute would be named customerId (GenRocket's camel-case convention), while its Original Name stays customer_id. Receivers such as the SQL-insert one use a separate columnName property key to write the real column name in the output.

18.5.1 Adding an attribute

  1. In the Domain Dashboard, click New Attribute, type a name and Save.

    The name matters, because GenRocket uses it to guess a generator.

  1. Look at the generator that was assigned, change parameters if needed and click Save Generator.

    What you should see: for firstName, the NameGen generator with parameters nameType, caseType, sortOrder, seed and waitAmount, and sample names in the preview.

To add columns that appeared later in the real database, the docs use Scratch Pad: type the existing domain name exactly as it is in GenRocket (not the table name), list the new column names, and choose Create with Generators.

18.5.2 Referencing one attribute from another, and the ordering rule

From docs Many generators have a reference parameter that takes another attribute's value. EmailGen, for example, can reference the id so each email is unique (user1@example.com, user2@example.com...). Double-click the reference field and pick the attribute with the plus button.

Only look upward

An attribute can only reference attributes above it in the list, because the engine fills attributes from top to bottom. Referencing one below returns an empty value. If you need to, click Rearrange Attributes and drag the attribute lower, then close the dialog to save.

Other attribute tasks, in brief: Copy an attribute to another domain or project version (rename it if copying within the same domain); use Group Edit to change one parameter on many attributes, or remove many attributes at once; and use the gear icon (Browse and Manage Attributes) to see which generators are in use.
