24.4 Rule sets: what they are and the four types

A rule set answers "which tables or files, of this connector, are in scope?". Profiling and masking jobs run only on what is in the rule set. A table added to the database later is not discovered or masked until you add it. Each rule set belongs to one connector, and the inventory (the per-column plan) hangs off the rule set. From docs

Open an environment and click the Rule Sets tab. The grid shows: Rule Set ID (for the API), Name, Connector Name, Source Type (Database, Fixed Width, Delimited, JSON, XML or DataSet), Metadata (the database or file type), a Refresh/Save status icon (database rule sets only; file rule sets show N/A) and Actions. You need View permission on Inventory and File Format to open a rule set's inventory.

Click + Rule Set and the engine first asks what kind of data the rule set holds. There are four choices.

24.5 Creating a database rule set

The Add Rule Set wizard has three steps: Details, Data Tables, Summary.

  1. Details: name the rule set and pick the connector.

    The name follows the usual naming rules (no special characters). The connector dropdown can be filtered by typing. When you choose one, the screen shows its details (database type, database name, host, port, schema, user), so you can confirm you picked the right database before going on.

    Connector details appear under the dropdown. Next is enabled.

  2. Data Tables: add the tables.

    Click Add Tables. A dialog lists the tables the connector can see (tables only, not views, indexes or stored procedures). Filter by substring or starts-with, tick the tables you want, or tick the header box for all, then Save.

    The selected tables appear in the grid with empty Logical Key, Filter and Custom SQL columns.

  3. Summary: review and Save.

    Check the configuration; Back fixes errors. Save stays greyed out if the rule set has no tables. Changing the connector resets everything you added.

    A bottom-sheet message with an Async Task ID. Follow it under Monitor > Async Tasks. When it finishes, the rule set shows in the grid.

Add every related table

The MS SQL driver page warns that any table with a foreign key linking to a primary key must be in the rule set. Add all four ShopSphere tables together (CUSTOMERS, ORDERS, ORDER_ITEMS, PRODUCTS). If a child table is left out and the parent's key is masked, the database will reject the change or the child rows will point at nothing.

24.5.1 Flat, semi-structured and copybook rule sets in one paragraph

For files, step 2 is called Data Files, and you click Add File Name (pick files the connector can see) or Add File Pattern (a Java regular expression, such as .*\.txt, is case sensitive). You then set properties that depend on the type: a format file (the description of the file's layout, created under Settings > Data Formats), end of record (Windows CR+LF or Linux LF, or a custom value), delimiter and text enclosure for delimited files, "Mask Whole File" for fixed-width files, and "Variable Length" for mainframe data sets. File name patterns work only for file-to-file jobs, not database-to-file jobs. Control characters can be entered as $[hex], for example $[01]. These are the topics of the file masking chapter.

24.6 Editing, refreshing, copying, deleting and verifying

All of these are in the Actions (...) menu of a rule set. The screenshot below shows the menu: Refresh, Edit, Duplicate, Delete and Checklist. From docs

  • Edit. The same wizard, pre-filled. Step 1 is read-only (name and connector cannot change). In Data Tables a read-only State column shows Added, Modified or Removed for rows you changed. Large rule sets load in batches and the grid becomes usable before the last batch arrives; "select all" before loading finishes affects only the rows loaded so far.
  • Remove tables. Tick them, click Remove Selected, then Confirm. A table already saved shows State "Removed" until you click Next and Save: nothing is deleted until the wizard's own Save.
  • Refresh. Rescans all tables and columns and refreshes the inventory, keeping existing algorithm assignments. The Refresh/Save icon turns into an hourglass while it runs and back to the circular arrow when done. Whether tables dropped from the source disappear depends on an API setting (refreshDropsTables). Refresh after the database schema changes, for example a new column.
  • Duplicate. Copies the rule set with its inventory and its filters. Give a new name and Save, then modify.
  • Delete. Deletes the rule set, its inventory and its filters.
Two "save" buttons

Many dialogs in this wizard (Add Tables, Edit Logical Key, filters) have their own Save. That Save only stages the change. Nothing is stored until you click the wizard's Save on the last step. If you close without it, your key is gone.
