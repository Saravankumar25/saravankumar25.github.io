The Test Data Manager web page has three main working areas: projects (the workspace), data sources (the tables brought in) and policies (what to protect, and how). This section covers where things live, why each task exists and what to expect afterwards.

11.1 Words to know first

View
One of the main screens of Test Data Manager, chosen from the tab bar at the top (for example Policies or Projects).
Content panel and Details panel
The two areas of most screens. The Content panel lists items (rows). The Details panel shows more about the row you selected.
Actions menu
A menu that changes with the view. Almost every task in this chapter starts with "click Actions".
Data source (in a project)
A set of source tables whose descriptions (metadata) you imported into the project. Not a copy of the rows.
Data domain
A named group of columns that mean the same kind of thing, such as "Social Security Number", recognised by column name or by value shape.
Regular expression
A short text code that describes a shape of text. [0-9]{3}-[0-9]{2}-[0-9]{4} describes "three digits, a dash, two digits, a dash, four digits".
Data pattern and metadata pattern
Two kinds of regular expression on a data domain. A data pattern describes what the values look like. A metadata pattern describes what the column name looks like.
Sensitivity level
A label you give a data domain to say how sensitive it is. An administrator defines which levels exist.
Policy pack
A ready-made policy installed with TDM, covering PII, PHI or PCI data.
Impacted Objects dialog
A warning window that lists what will break when you delete or change something that is already used.

11.2 Who uses which view

The guide ties each view to a typical person (User Guide 10.5.10, p.37). A compliance officer uses Policies to create policies, rules and data domains. A developer uses Projects to import sources, run profiles, define subset, masking and generation, and generate and run workflows, and uses Monitor to check job status. A test data specialist or test engineer uses Data Sets for the test data warehouse. An administrator uses Administrator for connections, pass phrases, workflow options and server management. By default an administrator can open the Administrator view; other users need privileges for the other views (p.39).

11.3 Logging in to Test Data Manager

You use a normal web browser and the user name and password defined in Informatica Administrator (User Guide 10.5.10, p.48).

  1. Open the address https://hostname:portnumber/tdm/ (or http:// if Transport Layer Security is off).

    hostname is the machine with the TDM Server. The guide's default port is 6643 with TLS and 6605 without.

    The Login dialog box appears.

  2. Enter your user name and password and choose the security domain, then click Login.

    If the domain uses LDAP, the default security domain is Native.

    Test Data Manager opens. Click Logout to leave.

11.4 The views

All views share a header (Search, Quick Links, User Preferences, Help, Logout) and a tab bar. Most screens have a Content panel (a list of rows) and a Details panel (more about the selected row).
