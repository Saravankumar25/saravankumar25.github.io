11.5 Helpers on every screen

Search field

The Search field finds objects inside the TDM repository and the test data warehouse repository: projects, plans, assignments, data sets and data set tables. It cannot search for connections (User Guide 10.5.10, p.39). Type all or part of a name and a search tab opens where you filter which object types to include, with a count of matches.

Results include the object plus things inside it and things that contain it. If you include projects, you will also see policies, rules and entities the project holds. Searching for a masking or generation rule returns the rule, its assignments, the objects containing it, and the dictionaries inside it. You cannot search while tables are being indexed.

Advanced search text filter

In some column filters you can type text instead of wildcards, and TDM picks the operator (p.39). Beginners use this constantly in big column lists.

Quick Links, User Preferences and Actions

  • Quick Links menu. Jump to content tabs for subset, masking and generation. It also has shortcuts to create a generation rule, masking rule, policy, data domain or project. What you see depends on your permissions (p.40).
  • User Preferences menu. Opens the Edit Preferences dialog with two tabs. General: tick Show Start Screen to see the Informatica Test Data Manager start screen at login. Projects: lists projects visible in Overview dashboards, where you can switch off the ones you do not want shown (p.40).
  • Actions menu. Modifies data you selected in the Content panel, or does tasks such as import and export. Its options change by view (p.40).

Data filter

The Content and Details panels can hold many rows. The guide's example: the Policies view lists 25 data domains and you type "Emp" in the data domain name filter, click the Filter icon, and see only names such as Employee_Domain or Emp_Number. Click the Reset Filter icon to clear it (p.40). It is the same idea as filtering a spreadsheet column.

11.6 The Overview view: dashboards

Overview is a set of summary reports (User Guide 10.5.10, pp.41-42). It shows graphs of how many masking, subset and generation objects exist, with links into projects and policies. Think of it as the "management view": you do not edit anything here, you notice what needs attention.

Why it matters

Project Risk Analysis is the dashboard a compliance officer opens first. If most columns sit outside any domain, either discovery has not run or the domains are too narrow. You will see the same idea again in the Informatica discovery and profiling chapter, where profiles assign columns to domains.

11.7 Policies, Data Sets, Monitor, Parameters and Administrator

  • Policies view lists policies, data domains and rules in the TDM repository. Select one to change it, or create a new one from the Actions menu. (We return to it in the policies section.) (p.43; screenshot p.43.)
  • Data Sets view lists data sets in the test data warehouse. Select a version to see general properties on the Overview tab; the Tables tab lists its tables; the Components tab lists its components. From the Actions menu you can reset a version to a target, delete a data set, or lock and unlock it. You can open a data set on its own page to view and edit data (p.43). The Informatica plans, workflows and warehouse chapter covers this.
  • Projects view lists projects. Select one to see its data sources and recent activities. From a project you define profiles, masking and subset and generate a workflow (p.44).
  • Monitor view lists jobs for tasks such as import, profiling, masking, subset and generation. Select a job and use the Actions menu. You can review the TDM Server job log, stop jobs and recover workflows (p.45). The guide's screenshot shows columns for Job ID, Name, Description, Status, Project, start and end time, and User.
  • Parameters view is the home of global parameters, those created outside any project. Use them directly in a plan or add them to a project first. You can filter, import, and export parameters as CSV (p.45).
  • Administrator view is where an administrator sets generation rule settings and child and parent record settings; defines data domain sensitivity levels; edits default project configuration fields; sets workflow properties, default staging and storage connections and storage tables; creates database connections and Hadoop connection details; manages dictionaries; views and searches application logs and sets log levels; integrates a test tool; and manages pass phrases (p.46).

You will not do most of the Administrator list yourself as a beginner, but you should recognise the words: when a masking run fails with a "connection" or "dictionary" message, this is the view the platform team opens.

11.8 The Expression Builder

An expression is a small formula that computes a value from columns and functions, similar to a spreadsheet formula. The Expression Builder helps you write one without remembering every function name (User Guide 10.5.10, pp.46-47). Click Expression to open it when you:

  • create masking rules of the Expression masking type;
  • add pre-processing or post-processing expressions to a standard masking rule;
  • create advanced masking rules;
  • assign rules to a column;
  • configure expressions in an ad hoc generation rule;
  • configure advanced expressions in plans.

It shows functions by category (expand All Functions for the full list). You pick columns, add a function with the Add arrow, and enter join conditions with operators. A Validate Expression button checks your formula.

Visual referenceInformatica TDM 10.5.10 User Guide, p.47, Figure "Expression Builder" (the Configure Expression window). What to look for: a Functions tab with categories (Aggregate, Character, Conversion, Data Cleansing, Date, Encoding, Numerical, Special, Test), an Expression box and a Join Condition box with operator buttons, and OK, Cancel and Validate Expression buttons.
Worked example, from the guide, retold for ShopSphere

The guide's example is an advanced masking rule with a first-name and a last-name input port, and two variable ports that receive the masked names. The output port joins them with a space:

CONCAT( CONCAT( VAR1, ' ' ), VAR2 )

In ShopSphere terms: VAR1 holds the masked first_name (for example a made-up name replacing "Asha") and VAR2 the masked last_name (replacing "Menon"). The output is a full name like "Priya Das". The expression is the guide's; the names are ours. The function syntax itself is documented in the Informatica Transformation Language Reference, which the guide points to and I did not read.
