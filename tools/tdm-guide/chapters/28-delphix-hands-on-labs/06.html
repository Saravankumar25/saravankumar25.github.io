28.12 Common mistakes and gotchas

Mistakes that cost the most time
  • Masking a database you cannot restore. Cancelling a running in-place job leaves semi-masked data, the docs warn. Snapshot first.
  • Believing SUCCEEDED means "all masked". Non-conformant values are skipped by default; read the non-conforming-data line of the summary every time.
  • Running a rule set with leftover assignments. A job masks every assigned column in its rule set.
  • Letting the profiler overwrite your choice. Untick Enable Automatic Updates before assigning by hand.
  • Trusting a file format without checking the data. A wrong field count or length silently drops or shifts data, and editing a shared format changes every file that uses it.
  • Using a non-unique algorithm where uniqueness matters. Name and lookup-style algorithms can collide; Character Mapping is the documented unique-output family.

28.13 Recap

Recap
  • The labs form a chain: connector, rule set and profile, files, FirstName, then text, SSN and phone.
  • A "connector to a VDB" is an ordinary database connector pointed at a VDB, a safe place to mask.
  • Profiling proposes; the inventory is where you decide. Turn off automatic updates before overriding.
  • Files need a format file: field names for delimited, names and lengths for fixed-width.
  • Verify with before/after queries, not job status alone. Explain every warning before sign-off.
  • CM Digits and CM Alpha-Numeric keep format with unique text output; Phone US gives fake but plausible numbers; FirstName is realistic but not unique.
  • Evidence is what you hand a reviewer, with each choice marked "docs" or "mine".
