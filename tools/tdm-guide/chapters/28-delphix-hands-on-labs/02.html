28.4 Lab 4: create a connector to a VDB

Goal and prerequisites

Create an application, an environment and a database connector so that the engine can reach the ShopSphere VDB, and prove the connection works. Every later lab depends on it. You need the setup data and "before" snapshot, plus from the DBA: database type, host, port, database name, schema, and a masking user and password. A wrong guess here is the most common reason Test Connection fails.

What "a connector to a VDB" means. The documentation describes database connectors and describes a VDB as a database that Delphix Continuous Data provisions (Delphix masking terminology); it describes no special "VDB connector". Create an ordinary database connector and point it at the VDB's host, port and database name. In-place masking rewrites data, so doing it on a disposable VDB keeps production untouched. (Masking as part of VDB provisioning is a separate setup with restrictions, described on Provision masked VDBs; this lab does not use it.)

Steps

  1. Log in and open the Environments page.

    Everything else (connectors, rule sets, jobs) hangs under an environment.

    A grid with ID, Application, Environment, Purpose and Approval, plus + Application, + Environment and Actions buttons.

  1. Add the application, then the environment.

    Click + Application, enter ShopSphere, Save: the docs say an application must exist before an environment can be created. Then + Environment: application ShopSphere, name ShopSphere_DB_Mask, Purpose Mask. Leave the approval-workflow box off: it makes an approver sign off a database inventory before any job runs, which suits real projects but is a hurdle in a first lab. Choose Save And View.

    The environment shows three empty tabs: Jobs, Rule Sets, Connectors.

  2. Open Connectors and click + Connection.

    The wizard has the steps Details, Credentials, Custom Properties and Summary.

  1. Details: name it and choose the type.

    Connection Name SS_VDB_Conn. Each Source Type entry is prefixed with its Meta Data Source ("Database - Sybase" in the screenshot). For Oracle, MS SQL Server and Sybase you also choose Basic (host and port) or Advanced (a full JDBC URL); pick Basic unless told otherwise.

  1. Credentials: the database facts.

    Fields depend on the type. The docs list Schema Name (the schema holding the tables), Database Name (case-sensitive: it must match what the instance knows), Host Name/IP, Port (SQL Server defaults to 1433), SID (Oracle) and Instance Name (SQL Server: if given, the port is ignored and port 1434 of the SQL Server Browser Service is used, so the firewall must allow it). Then the masking user's name and password.

    All required fields filled; the password shows as dots.

  1. Skip Custom Properties.

    That step uploads a Java properties file. The docs warn that its values are readable by anyone who can view connectors, so secrets belong in the form fields.

  2. Click Test Connection, then Save.

    The docs say the engine uses the wizard's information to attempt a database connection and reports success or failure. Testing before saving lets you fix mistakes while the form is open.

    A success message. After Save, SS_VDB_Conn appears under DATABASE with a Connector ID.

  3. Test the saved connector from the grid.

    Open the row's actions menu and choose Test Connection. This proves the saved connector works, not only the form.

Verification checks

  1. Test Connection succeeds twice (wizard and grid); screenshot the message.
  2. SS_VDB_Conn is under DATABASE with an ID and no warning triangle. The docs say the numeric ID is how the masking API refers to the connector.
  3. With the masking user in your SQL client, SELECT COUNT(*) FROM customers; returns 3.
  4. Record the exact database name, schema and host.
