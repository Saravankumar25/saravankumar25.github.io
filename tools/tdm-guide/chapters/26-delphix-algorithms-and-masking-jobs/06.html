26.13 Common mistakes and gotchas

Watch out for these
  • Using a non-unique algorithm on a key or unique column. Secure Lookup, Name and Date Shift Discrete can collide. Use Character Mapping, Segment Mapping or Mapping for keys, and the same algorithm on every column that must still match, including foreign keys.
  • Ignoring the yellow Warning status. Non-conformant values are left unmasked by default, so real data can reach the test database. Read the Error Report after every run.
  • Testing for "zero unchanged values" with name algorithms. The documentation says a masked name can equal the input; test for "a small number", and use Character Mapping when a changed value is mandatory.
  • Running an in-place job on the only copy of the data. Cancelling or failing midway can leave data semi-masked, and dropped indexes or triggers are not recreated.
  • Several update threads on tables without indexes. The docs warn of deadlocks, especially on T-SQL databases.
  • Re-keying an algorithm casually. It changes every masked value, so test data from before and after no longer matches.
  • Letting the profiler overwrite your algorithm choice. Untick Enable Automatic Updates when you assign by hand (see the profiling chapter).
  • Assuming a masked SSN or phone number is a valid real-world number. The frameworks keep shape and uniqueness, not issuing rules.
  • Giving a job too little memory. Below the recommended 1024 MB, and with large lookup files or mappings, performance suffers or jobs fail.

26.14 Recap

Key points
  • A framework is a configurable kind of algorithm; an instance is a ready recipe you assign to a column. Output is repeatable for the same input, key and configuration.
  • Lookup frameworks (Secure Lookup, Name) pick a line from a list file and may collide. Character Mapping and Segment Mapping are keyed and collision free, which suits keys and identifiers.
  • Algorithms used in the labs: dlpx-core:FirstName for first names, Segment Mapping or CM Digits for SSN, dlpx-core:CM Alpha-Numeric for alphanumeric text, dlpx-core:Phone Unique for telephone numbers.
  • A masking job is in-place (changes the data where it sits) or on-the-fly (reads a source, writes a target). Key settings: commit size, update threads, batch update, streams, row limit, memory, pre and post SQL.
  • Run the job, then monitor status, components, logs and the Error Report; non-conformant data is left unmasked by default.
  • Always verify with SQL: row counts, side by side, distinct counts, uniqueness, format and join checks.
