26.5 Deep dive: masking a first name

The default tool is dlpx-core:FirstName, an instance of the Name framework. It needs String input. If the value is null, empty or only spaces, it comes back unchanged. Words joined by a hyphen count as one word, a single letter is treated as an initial and masks to a single letter, and by default at most two names are masked and extra ones dropped. It raises no non-conformant data errors, and it can occasionally mask a name to itself From docs.

26.6 Deep dive: alphanumeric text with Character Mapping

Character Mapping swaps each maskable character for another one from the same group, using a key. You define groups such as [0-9] and [a-zA-Z]; a digit becomes a digit and a letter a letter; anything not in a group (dashes, spaces) is left alone. Every maskable position affects every other, no two text inputs share an output, and a masked value never equals the original if at least one character is masked. That makes it suitable for keys and identifiers From docs.

Three ready instances cover most needs:

InstanceMasksUse onDocumented example
dlpx-core:CM Alpha-NumericDigits, lower and upper case letters, some Latin and CyrillicText columns only"ABCxyz123" to "HANwhp391"
dlpx-core:CM DigitsOnly ASCII digits; letters and symbols stayText columns holding numbers (codes, ids)"ABCxyz123" to "ABCxyz391"
dlpx-core:CM NumericDigits, keeps digit count; first digit never 0Numeric database columns"99" to "75"

If no character at all is masked (say, CM Digits on "ABC"), the engine records non-conformant data. CM Numeric also ignores database numeric limits, so on DB2 INTEGER or SQL Server INT columns a masked value can exceed the range and cause a conversion error.

26.7 Deep dive: SSN with Segment Mapping (or Character Mapping)

An SSN has structure (3 digits, dash, 2 digits, dash, 4 digits) and often serves as a lookup key, so you want unique, format-preserving output. The Segment Mapping page names Social Security Numbers as a typical use and describes exactly the controls you need From docs:

  • Up to 10 segments, each up to 6 characters, each treated as Mask alpha-numeric, Mask numeric, Preserve or Mask with a constant value.
  • Ignore characters (such as the dash) are removed before masking and put back afterwards, so "123-45-6789" and "123456789" mask alike.
  • Numeric segments are masked as whole numbers, alpha-numeric ones character by character.
  • Values must match the segment pattern; data longer than the pattern passes through unmasked, and short numeric segments are reported as non-conformant unless you choose "Mask partial segments".

Two alternatives exist. CM Digits (or CM Alpha-Numeric) masks every digit and keeps the dashes automatically, with no setup: the docs' examples turn "999-12-3456" into "453-71-6283" (Character Mapping framework, group [0-9]) and "999-12-3456." into "668-23-1138." (CM Alpha-Numeric). Redact Digits-Zero turns every digit into 0 ("999-12-3456." to "000-00-0000."), which is not unique: many different SSNs become the same value.

Accuracy flags for SSN

The documentation excerpt I had does not say which algorithm the SSN domain uses by default; look at Settings > Domains on your engine. It also does not promise that a masked SSN follows real issuing rules (the profiler's patterns exclude area numbers 000 and 666, for example). If your application validates SSNs, test the output, and consider restricting a numeric segment's mask value range.
