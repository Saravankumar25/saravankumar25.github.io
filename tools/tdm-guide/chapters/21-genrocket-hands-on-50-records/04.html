21.7 Verification checks

A file that "looks fine" in the first few rows can still be wrong in row 37. Check it deliberately. The commands below are general shell commands (macOS, Linux or Git Bash on Windows), not from the GenRocket documentation; a spreadsheet can do the same with COUNTA, LEN and conditional formatting.

Full checklist before you call the lab finished:

  • The file is where resource.output.directory says, and is named Customers.csv.
  • Exactly 50 data rows; the header is present once.
  • Only the four wanted columns: no id, no middle name.
  • No empty or "null" cells in any column.
  • Full Name equals FirstName, a middle name and LastName for every row.
  • All phone numbers have the same length and are unique.
  • Running the scenario a second time still gives 50 rows, not 100 (appendToFile false). If you set a seed, the names are the same as before.
Why verify at all?

Test data is an input to other tests. If the data silently has 49 rows or an empty phone, every test that uses it can fail for reasons that have nothing to do with the application. A five-minute check protects hours of debugging.

21.9 Extension lab: an email and a nullable column

Lab: add Email and a nullable Alternate Phone

Goal: the same 50 rows with two more columns, one of them sometimes empty. This puts the null pattern from the null and blank section of the patterns chapter into practice.

  1. Add email with EmailGen.

    New Attribute email; names containing "email" get EmailGen automatically. From docs Its parameters are prefix (the local part), reference (another attribute, to make the local part unique), suffix (the first part of the domain) and extension (com, net and so on) (EmailGen). Set prefix user, reference the id attribute, suffix example, extension com. Referencing id makes each address unique.

    Preview shows addresses like user1@example.com (based on the pattern in the vendor's API example).

  2. Add alternatePhone and make it nullable.

    Give it PhoneNumberGen with areaCode 900 so it differs from the main phone. On the Attribute Dashboard set % Null to 30. That field is "the percentage of time the null value is used for negative testing". Click Save.

    Preview shows a mix of numbers and empty or null cells.

  3. Decide how null is written.

    On the receiver, check nullValue (default (null) in the screenshot). Set it to an empty string if your consumer expects an empty cell. Add the two attributes to the receiver's Attributes Property Keys with column names Email and Alternate Phone.

  4. Download and run again.

    The earlier checks change: six columns; no empty values in the first four; roughly 15 of 50 Alternate Phone cells empty (the docs give no exact count for % Null).

Idea: ten-digit phone numbers instead

ShopSphere's sample phones are 10 plain digits. Make phoneNumber a linked set: gen1 PhoneNumberGen, gen2 StringReplacementGen with value #{self.gen1}, fromText \D and toText empty. The StringReplacementGen page says a match with no replacement is removed, and lists \D as "any non-decimal digit" (StringReplacementGen). Expect 8006001000 for the first row, 10 characters, but check the Preview. For a nullable phone, EmailGen-style: use % Null as above.

21.10 Extension lab: customers with a varying number of orders

Real data has parents and children: one customer, several orders. GenRocket models this with a parent domain and a child domain, and each domain "has one parent but many siblings" (manual parent and child relationships). This lab follows the vendor's page "How to generate Children based on Weights (Percentages)" (link), with ShopSphere names.

Lab: 10 customers, each with 1, 2 or 3 orders

Goal: 10 customers; 5 of them (50 percent) have 2 orders, 2 (20 percent) have 3 and 3 (30 percent) have 1. Total orders: 19.

  1. Create the child domain and set the parent.

    Create a domain Order with a RangeGen order id and a delimited receiver (as in the main lab). In Order's Domain Dashboard open the Relationship tab, click Add Referential Parent, choose Customer, Save. Set Customer's loop count to 10. A parent domain must exist so that each order points at a real customer.

    A small diagram shows Customer above Order.

  2. Add an attribute to the parent that holds the child count.

    In Customer, add childLoopCount, untick Visible (it is a helper), and replace its generator with MultiWeightGen: valueList 2, 3, 1; percentList 50, 20, 30; exactPercentage True. Save Generator.

    The attribute exists, hidden, and its preview shows 2, 3 and 1.

  3. Create the scenario for the child and point its loop count at the parent's attribute.

    Create a scenario with Order as the primary domain (Quick Scenario adds the parent). On the Scenario Dashboard double-click Order's Loop Count Value, choose the Domain Attributes tab, select Customer, click + beside childLoopCount, and save with the disk icon.

    The Summary column reads "N Order for each Customer", where N comes from childLoopCount.

  4. Download and run.

    Run genrocket -r <scenario>.grs. From docs The vendor's output shows ten users with 3, 1 or 2 addresses in the stated proportions, as the annotated screenshot shows.

    19 order rows. Count orders per customer id: five customers with 2, two with 3, three with 1.

Show a foreign key column and notes

To carry the customer id into each order, the vendor's design is a placeholder at domain level and a real reference at scenario level. From docs The ProxyReferenceGen page says it is "a proxy (or placeholder) to reference another value", that attributes can only talk to parent or sibling domains within a scenario, and that it should then be replaced by a ReferenceGen, which is assigned automatically for imported domains. It gives separate manual steps for hand-built parent and child domains (its "Use Case Example 2"), referencing the parent's primary key (ProxyReferenceGen; ReferenceGen). Follow that page and check the Preview.

21.12 Recap

Recap
  • A TDG plan has four stages: use cases, proof of concept, environment assessment and deployment plan. The 50-record lab is a POC.
  • Lab path: project, domain Customer, loop count 50, five attributes, a DelimitedFileReceiver, a scenario, download, genrocket -r, open the file.
  • FirstName and LastName use NameGen (nameType firstName and lastName); the middle name uses NameGen too, because no middle-name type is documented.
  • Full Name is a ConcatGen whose list references the three name attributes with spaces between; it must sit below them, and the helper attribute is hidden with Visible off.
  • Phone Number is PhoneNumberGen, a sequence of numbers.
  • The receiver's columnName and include property keys set the headers and drop id; appendToFile false keeps reruns at 50 rows.
  • Verify the output: 50 rows, four columns, no empties, consistent Full Name, equal-length unique phones. Download the scenario again after every change.
  • Extensions: EmailGen and % Null for a nullable column; MultiWeightGen for child counts; ListGen with setLoop for boundary rows.
