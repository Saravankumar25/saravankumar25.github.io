You have described the data (domains, attributes and generators). Two jobs remain: say what format the rows must arrive in, and say how many of what, in which order. The first job belongs to receivers, the second to scenarios. Once both exist, you download the scenario, run it with the GenRocket Runtime, and files or database rows appear.

This chapter explains receivers (the common ones in detail, the rest by family), then scenarios, scenario chains and related controls, and finishes with an end-to-end ShopSphere build and a troubleshooting table. Patterns and the 50-record hands-on exercise follow in the data patterns chapter and the GenRocket hands-on chapter.

19.1 Words to know first

Receiver
The component that takes a domain's raw generated values and writes them in a usable format: file, database insert, message and so on.
Receiver parameter
A setting for the receiver as a whole (where to write, what to name the file). A star in the web platform marks required ones.
Attribute property key
A setting for one attribute within a receiver, such as columnName (the header or column) or include (leave it in or out).
Output format
The shape of the result: delimited file, fixed-width file, JSON, XML, Excel, SQL statements and many others.
Organization resource
A named folder setting that each user fills in with their own path, for example resource.output.directory. Receivers refer to it instead of a hard-coded path.
Scenario
The saved instruction sheet: a primary domain, its parents, how many rows of each, and which receivers run.
Primary domain and root domain
The primary domain is the one the scenario is built for. The root is the first parent at the top of the chain.
Scenario chain
Several scenarios linked so that one command runs them in order.
.grs file
The downloaded, encrypted scenario file that you run with genrocket -r.
Stateful scenario
A scenario that remembers generator positions between runs, so a counter continues where it stopped.

19.2 Receivers

19.2.1 What a receiver is, and what it supports

From docs A receiver receives unformatted raw data from a generator and "morphs it into a usable output format". The overview says 120+ types exist (the count grows), and groups what they reach: SQL databases, NoSQL databases such as MongoDB, web-service formats (REST, SOAP, XML, JSON), fixed-file formats (CSV, Excel, VSAM, NACHA, BAI2), big-data formats (Parquet, Avro), message formats (Kafka, MQ, SWIFT), packaged applications (Salesforce, SAP, Guidewire, Duck Creek), complex feeds (X12 EDI, FHIR), documents and images (PDF, JPEG, TIFF, PNG), and cloud services.

The vendor's receiver browser lists sixteen categories:

The "Supported Output Formats" page is a large checklist rather than prose. For each format it marks whether GenRocket supports it, whether the vendor validated it, whether a bulk-load receiver exists, and for databases whether a JDBC driver exists. It also notes that a missing format can be requested from the vendor. Use it when a project asks "can you produce X?".

Why it matters

Receivers are why the same design can feed a CSV for a spreadsheet user, SQL inserts for a database tester and JSON for an API test. You never change the generators for that, only add or swap a receiver. More than one receiver may be attached to a domain: they run in the order listed, which is useful when you need several outputs or several folders.

19.2.2 Adding a receiver to a domain

  1. Open the domain's dashboard and click New Receiver in the Domain Receivers pane.

    A receiver must be on a domain before its values reach any output.

  1. Click the plus on the receiver, optionally rename it, and click Save.

    The name only has to be unique within the domain.

  2. If scenarios already exist for the domain, tick the ones that should get the receiver and click Add Receiver.

    Receivers copied into scenarios are separate from the template. Without this step, old scenarios will not have the new receiver.

  1. Fill in the required parameters (marked with a star) and click Save.

    What you should see: the receiver listed in the Domain Receivers pane of the Domain Dashboard.

Many domains at once. In the Domain Dashboard open the Global Editing menu and choose "Add a New Receiver to Multiple Domains". This opens the Receiver Assignment Wizard: take ownership, choose the receiver and its parameters, filter to the domains, and execute. The vendor's example adds a DelimitedFileReceiver to the Department, User and Address domains in one pass.

19.2.3 The Receiver Dashboard

Click a receiver's name to open its dashboard. Four tabs matter.

TabUse
ParametersThe receiver's own settings. Starred ones are required to download and run a scenario
Attributes Property KeysPer-attribute settings such as column name and include. Drag attributes to reorder output columns, use Sync Receiver Attribute Order, or the name-conversion menus (camel case is the default)
File ConfigWhen available: when to start a new output file (for example by a count) and how to name files dynamically
Directory ConfigWhen available: how many files per sub-folder and how to name sub-folders

The column order of an output file normally follows the attribute order in the domain, which is shaped by the rule that attributes only reference attributes above them. If that order is not what the consumer wants, drag the attributes into the desired order in the Attributes Property Keys tab.

19.2.4 Output folders: organisation resources

Receivers do not hold a user's folder name. They use resource references. A new account has three: resource.home.directory, resource.jdbc.directory and resource.output.directory (the dashboard screenshot in the overview chapter shows them). The resource page recommends the home directory be the real home folder, and the other two be different folders, preferably sub-folders of home, because using the same path for all three can cause errors "or, in some cases, a process that never finishes". After changing any resource value you must download your profile again and replace the old file in .genrocket; otherwise you get the error "Unable to Download Users Profile" if a resource has no value, or stale paths if you forget.

19.2.5 Configuration files, V2 receivers and bulk load

  • Configuration file. A file that tells a merge receiver how to combine data from different domains into one nested output. It defines file name segments, the segment files and the element layout. It is created in the Configuration Management tab and its name goes in the merge receiver's configName. Some imports (JSON, XML) create one for you.
  • V2 receivers. Names contain "V2" just before "Receiver", for example GenericSQLInsertV2Receiver. They add two parameters, resourcePath and resourceSubDir, so a receiver can point to different configuration folders without creating more global resources. The vendor says V1 receivers will eventually be hidden from the picker; scenarios that already use them keep working.
  • Bulk load receivers. Inserting through JDBC averages about 4,000 records per second, according to the page, which is slow for millions of rows. Bulk-load (partition) receivers write the database's native bulk-load file format instead. The page lists receivers for MySQL, Oracle, PostgreSQL, MS SQL, DB2, Sybase, Snowflake, Databricks, Parquet and delimited files.
