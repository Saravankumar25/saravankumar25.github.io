Not all sensitive data sits in a database. Customers export spreadsheets, partners drop .dat feeds on an SFTP server, and batch jobs write flat text files that testers later load. A masking project has to cover those files too. The good news is that Delphix masks files with the same algorithms and the same ideas you have already met: a connector, a rule set, an inventory and a masking job. The new piece is the file format: because a text file has no built-in column names, you must tell the engine where the fields are.

This chapter teaches that from zero and ends with the Day 53 lab (TDM_Handson6): masking a ShopSphere customers.dat file end to end. Connectors and rule sets are introduced in the connectors chapter and the rule sets chapter; profiling and the inventory are in the profiling chapter; the algorithms and job options come from the algorithms and masking jobs chapter. Flat-file basics are also in the data basics chapter.

27.1 Words to know first

Flat file
A plain text file where each line is a record and each record holds fields in a fixed order, such as a .txt, .csv or .dat file. The extension is only a habit; the engine cares about the layout.
Record / field
A record is one line (one customer). A field is one value in it (the phone number).
Delimited file
Fields are separated by a character such as , or |.
Fixed-width file
Every field has a set length, so field two starts at a known position, with no separator.
File format (definition)
A small description file you upload that lists a file's field names (and, for fixed width, lengths). It is metadata only. Many data files can share one format.
End-of-record
The character or characters that end a line: LF on Linux, CR+LF on Windows.
Text enclosure
A character, often a double quote, that wraps a value so the value may contain the delimiter. "Menon, Asha" is one field.
Escape
How a literal enclosure character inside an enclosed value is written, by default by doubling it.
Record type and qualifier
When one file mixes record layouts, a record type names each layout and up to three qualifiers say how to recognise it.
Header and footer
Lines at the start or end that should be copied through unmasked.
File connector / rule set
The connector says where the files are. The file rule set lists which files (or name patterns) to process and which format each uses.
Encoding
How characters become bytes. ASCII and UTF-8 are supported for the main file types; mainframe data must be EBCDIC.

27.2 How a text file becomes fields the engine can mask

A database table knows its own columns. A text file does not. Here is the ShopSphere sample used throughout this chapter, as a pipe-delimited file. All data is fake.

customer_id|first_name|last_name|email|phone|ssn|date_of_birth|zip_code|tax_id
1001|Asha|Menon|asha.menon@example.com|9876543210|123-45-6789|1990-04-12|560001|ABCDE1234F
1002|Ravi|Kumar|ravi.k@example.com|9123456780|234-56-7890|1985-11-02|600017|PQRST5678K
1003|Meera|Nair|meera.n@example.com|9988776655|345-67-8901|1999-07-23|682001|LMNOP9012Q

To the engine this is just characters. For it to apply "first name algorithm to field 2", it needs a map: field 1 is customer_id, field 2 is first_name, and so on. That map is the file format. The rest of the chain mirrors databases:

→
Connectorwhere the files live
→
Rule setwhich files, which format
→
Inventoryfield → algorithm
→
Masking jobreads, masks, writes

The docs state the reason directly: unlike databases, files typically carry no built-in metadata describing their fields, so you supply it in Settings > Data Formats From docs.

Look at the file before you describe it

The extension (.txt, .dat, .csv) tells the engine nothing; only the layout matters. Before you write a format, answer four questions about the actual file. These commands are ordinary Linux tools, not Delphix features, and are my suggestion:

head -3 customers.dat                      # what separates the fields?
cat -A customers.dat | head -2             # $ marks LF; ^M$ means CR+LF (Windows)
awk -F'|' '{print NF}' customers.dat | sort | uniq -c   # same field count on every line?
file customers.dat                         # ASCII or UTF-8 text?

If cat -A shows ^M$ at line ends, the end-of-record is CR+LF. If the field counts vary, the file has several record layouts or stray delimiters, which points to record types or enclosures.

The same ShopSphere record as fixed width, with lengths 6, 12, 12 and 30, looks like this (dots stand for padding spaces):

1001..Asha........Menon.......asha.menon@example.com......
^1-6  ^7-18       ^19-30      ^31-60

Field 2 starts at position 7 because field 1 is six characters long. The engine computes every start from the lengths you list, which is why one wrong length shifts everything after it.

27.4 Delimited versus fixed-width, and the characters that matter

Delimited

Fields separated by a delimiter. Needs: the delimiter, optionally a text enclosure, an end-of-record. Fields can have any length. The format file lists field names, one per line, and no header.

Sample: 1001|Asha|Menon

Fixed-width

Fields occupy fixed positions. Needs: an end-of-record and exact field lengths. The format file lists name,length per line. Length is counted in characters, not bytes, so multi-byte characters count once.

Sample: 1001Asha Menon

End-of-record

Choose LF for Linux-style files and CR+LF for Windows-style ones in the rule set's file properties. The docs do not describe the failure mode; my expectation is that a wrong choice glues lines together or leaves a stray carriage return in the last field. The rule set page also lets you use a control character as delimiter or end-of-record: click the CTRL button for a virtual keyboard, or type it as $[hex value], for example $[01] for ^A. The docs say to avoid typing ^t or \t From docs.

Enclosures and escaping

Take the line 1004|"Rao, Kiran"|... with a pipe delimiter and a double quote enclosure. The comma inside the quotes belongs to the value. If a value itself contains a quote, it must be escaped. The rule set offers an Enclosure Escaping Strategy From docs:

  • Double Enclosure (the default): the escape character is the enclosure character, so "" means one literal quote.
  • Custom: any single character except escape sequences and control characters.
  • Escape "Enclosure Escape Character" (checkbox): the escape character can also escape itself, so with * as escape, ** is one literal *.

For a large number of rule sets the docs provide an API script that updates these settings through PUT /file-metadata, for all delimited rule sets with an enclosure or for one rule set ID. A custom escape character or the "escape the escape" flag is not supported for delimited fields holding structured (JSON or XML) data; only double enclosure is.
