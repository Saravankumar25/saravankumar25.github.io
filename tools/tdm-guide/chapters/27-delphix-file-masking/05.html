27.13 Lab: mask a ShopSphere customers.dat file

Lab: from a text file to a masked file

Goal: mask customers.dat in place on a file server, using a delimited format, a connector, a file rule set, algorithm assignments and a masking job, then verify the output with shell commands. Use a work copy on a disposable path, never a real feed. Names such as customers_delimited.fmt and /data/shopsphere/work are examples. The algorithms were introduced in the algorithms and masking jobs chapter.

  1. Create the sample file on the file server and keep an untouched backup elsewhere.

    Use the four lines shown earlier, saved with LF line endings. Put customers.dat in /data/shopsphere/work/ and a copy named customers.dat.orig somewhere the connector cannot see, such as your home directory. You need the original to prove the change.

    The work directory holds exactly one file.

  2. Create the format definition customers_delimited.fmt: nine lines, one field name per line, in file order, no header.

    customer_id, first_name, last_name, email, phone, ssn, date_of_birth, zip_code, tax_id. The first line of data is a header, but the definition lists names only.

  3. Import it: Settings > Data Formats > + File Format > Delimited, choose the file, set 1 header record and 0 footer records, Save.

    The header line customer_id|first_name|... is then copied through unmasked instead of being treated as a customer.

    A format named customers_delimited.fmt of type Delimited appears in the File tab.

  4. Create the connector: Connectors > + Connection, Source Type File - Delimited, mode SFTP (or Filesystem Mount Point), server, port, path /data/shopsphere/work, credentials. Click Test Connection, then Save.

    The connector's path is where the engine looks for files.

    Test Connection reports success.

  5. Create the rule set: Rule Sets > Add Rule Set > Flat Files, name ShopSphere_Files, choose the connector, then in Data Files click Add File Name, tick customers.dat, and set Format File to customers_delimited.fmt, End of Record LF, Delimiter |, Text Enclosure blank. Save, Next, Save.

    Delimiter and end-of-record are properties of the data file, not of the format.

    The rule set shows Source Type Delimited with one file.

  6. Optional: run a profiling job on the rule set (see the profiling chapter) to see which fields the ASDD profiler flags.

    Field names such as first_name, ssn and email are recognisable, so most fields should be flagged. Compare with your plan below.

  7. Open the inventory and assign algorithms, one Edit per field, unticking Enable Automatic Updates first.

    Plan: first_name FIRST_NAME with dlpx-core:FirstName; last_name LAST_NAME with dlpx-core:LastName; email EMAIL with dlpx-core:Email Unique; phone TELEPHONE_NO with dlpx-core:Phone Unique; ssn SSN with your SHOPSPHERE_SSN or dlpx-core:CM Digits; date_of_birth DOB with a Date Shift algorithm and Date Format yyyy-MM-dd; zip_code ZIP with dlpx-core:CM Digits; tax_id TAX_ID with dlpx-core:CM Alpha-Numeric. Leave customer_id unassigned.

    Eight fields carry an algorithm; customer_id has none.

  8. Create the job: + Masking Job, name ShopSphere_Mask_File, In-Place, rule set ShopSphere_Files. Configuration: 1 stream, memory 1024, Save. Run it from the "..." menu.

    There is no database step for file rule sets.

    Status Queued, Running, Succeeded. Execution Components lists customers.dat with 100% progress.

  9. Verify with the commands below.

    Run them in the work directory and compare to the expected results.

# 1. line count and header
wc -l customers.dat customers.dat.orig
head -1 customers.dat

# 2. every line still has 9 fields
awk -F'|' '{print NF}' customers.dat | sort | uniq -c

# 3. no original value survives in the columns that use unique-style algorithms
for c in 4 5 6 9; do
  cut -d'|' -f$c customers.dat.orig | tail -n +2 > /tmp/orig_$c.txt
  echo "column $c exact matches:" $(cut -d'|' -f$c customers.dat | tail -n +2 | grep -c -x -F -f /tmp/orig_$c.txt)
done

# 4. SSN shape (expect 0) and duplicates (expect 0)
cut -d'|' -f6 customers.dat | tail -n +2 | grep -c -v -E '^[0-9]{3}-[0-9]{2}-[0-9]{4}$'
cut -d'|' -f6 customers.dat | tail -n +2 | sort | uniq -d | wc -l

# 5. customer_id untouched
diff <(cut -d'|' -f1 customers.dat.orig) <(cut -d'|' -f1 customers.dat) && echo ids identical

# 6. no leftover temporary file, same owner and permissions
ls -la
Show a worked answer

Expected results.

  • Command 1: both files have 4 lines; the first line of the masked file is still the header.
  • Command 2: 4 9, meaning four lines with nine fields each. A different number means the delimiter or format is wrong, or a masked value contained the delimiter.
  • Command 3: all zeros. The algorithms for email, phone, SSN and tax id are designed to change every value. Do not run this check for names: the docs allow a masked name to equal the original.
  • Command 4: 0 and 0. The shape holds and the SSNs are unique.
  • Command 5: "ids identical".
  • Command 6: only customers.dat is present. The hidden .msk temporary file used by in-place masking has been renamed over the original, and owner and group are unchanged.

An example masked line (values will differ): 1001|Nimisha|Haldane|XF35TNMKPPTMQF4CX5264ZRXOMJJL2DQVE3KTZNIJ2NS6EUH7GLA@example.com|9874120685|804-27-1956|1990-04-17|312904|KMQTR6021Z. Notice: the email is the long Email Unique form, the phone keeps its first three digits, and the date moved five days with the same format.

If it did not work. Nothing masked but status Succeeded: the file name or pattern does not match any file on the connector path. Fields shifted: wrong delimiter or format. Header masked: header count is 0. Extra characters at line ends: end-of-record should be CR+LF if the file came from Windows. Job fails on missing file: the connector path is wrong.

Mini exercise: a fixed-width version

Goal: see why lengths matter. Make a format customers_fixed.fmt with lines customer_id,6, first_name,12, last_name,12, and a data line 1001 Asha Menon .

  1. Import it as Fixed Width, add a fixed-width rule set and assign dlpx-core:FirstName to first_name.

    The format gives the start position of each field from the cumulative lengths.

  2. Change first_name to length 10 and rerun on a fresh copy.

    The masked first name no longer lines up with the original field: the engine now reads characters 7 to 16 as the first name, so part of the last name and padding get masked or left behind. This is predicted from the docs' warning about wrong lengths; try it and look.

27.14 Common mistakes and gotchas

Watch out for these
  • Uploading real data as a "format". Format files are schema only. A copy of last week's feed in the format dialog puts real values in the engine.
  • Forgetting that a format is shared. Editing fields or algorithm assignments for one file changes every file and rule set that uses the same format.
  • Wrong delimiter or end-of-record. The job may succeed while masking the wrong text. Open the output and look.
  • Header not declared. The header row is masked as if it were a customer.
  • Field count mismatch. Extra fields are silently dropped and missing ones are padded with delimiters.
  • Wrong fixed-width lengths. Every later field shifts. Count characters, not bytes.
  • File name pattern that matches nothing. The job can still end in success, so read the Execution Components.
  • Windows line endings in the format file. Use LF to avoid parsing failures.
  • Assuming UTF-16 or other encodings work. The docs list ASCII and UTF-8 (UTF-8 for Parquet, EBCDIC for mainframe).
  • Treating a masked file as safe without checking it. Run the verification commands and grep for known real values.

27.15 Recap

Key points
  • Files have no built-in column names, so a file format definition (schema only) maps positions or names to fields. Formats are global and shared.
  • Delimited files need a delimiter and end-of-record (and optionally an enclosure and escape strategy); fixed-width files need exact lengths.
  • Record types with up to three qualifiers handle mixed layouts; header and footer counts protect unmasked lines.
  • Connectors reach files by filesystem mount, SFTP, FTP or FTPS, S3, S3-compatible storage and Azure Blob; mainframe data needs EBCDIC and a copybook.
  • A file rule set lists files or patterns and gives each its format, end-of-record and delimiter; the inventory assigns algorithms to fields.
  • In-place file masking writes a hidden .msk file and replaces the original on success; on-the-fly writes to a separate target and is faster.
  • Always verify the output file: line counts, field counts, original values gone, unique fields still unique.
