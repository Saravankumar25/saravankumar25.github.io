27.5 File format definitions

Open Settings > Data Formats. The File tab lists formats with ID, Name and Type (Delimited, Fixed Width, XML, JSON, Parquet); the Mainframe tab holds copybooks. Click a name to open it.

Two rules from the docs

Schema only. Upload field names, never production data, sample records or PII; for XML, JSON and Parquet use empty tags, nulls or dummy values. Global effect. A format is shared: changing its inventory changes every data file that uses it, in every rule set. The format screens show a banner saying so From docs.

Build a format file

You create the definition as a small text file, then import it.

File typeWhat the definition file contains
DelimitedField names, one per line, no header
Fixed-widthField name, a comma and the length, one per line, no header
XML, JSONAn example document with the structure only
ParquetA schema-only file, or a .txt or .fmt file listing the schema
MainframeThe COBOL copybook itself (duplicate field names are not supported)

If your data does not match the format, the docs describe two behaviours for delimited files. Fewer fields than the format: delimiters are added after masking to reach the full count (Data1,Data2 becomes Masked1,Masked2,). More fields than the format: the extras are lost (Data1,...,Data4 becomes three masked fields). In both cases the output no longer matches the input shape, so keep formats accurate. For fixed-width files a wrong length shifts every later field, so you mask the wrong characters. On Windows, save format files with LF line endings, since CRLF can pass your eye but fail the engine's parser From docs.

Import a format, step by step

  1. Settings > Data Formats > File tab > + File Format.

    The wizard opens at Format Type.

  2. Choose the type (for example Delimited) and click Next.

    The wizard shows formatting examples for each type.

  3. Import Format: optionally name it, click Choose File, select your definition file, Next.

    If you leave the name blank, it takes the uploaded file's name.

  4. Delimited and fixed-width only: set the number of header or footer records, or leave them empty, then Next.

    These records are copied to the output unmasked.

  5. Review Summary and Save.

    The format appears in the File tab with its type.

From the same list you can edit, Duplicate (with an option not to copy masking assignments), Export and Delete a format. Exporting an XML or JSON format gives a template with placeholder values; namespaces in exported XML must be copied back by hand before reuse From docs.

27.6 Record types, qualifiers, header and footer

Real feeds often mix layouts in one file. The docs' example has lines like address, account1234, 9A Lexington Street, ... and email, account1234, bar@example.com: the first field says what kind of record follows. A record type describes one layout; up to three qualifiers (a field plus a regular expression) tell the engine which lines belong to it. A line gets exactly one record type, and if several qualifiers match, the engine cannot guarantee which wins. Record types and header/footer apply only to delimited and fixed-width formats, and can be managed only on the Formats page, not on the inventory page From docs.

  1. Add a record type: + Record Type, enter a Record Name, Choose File (a definition file for that layout), Save.

    Each layout needs its own field list.

  2. Add qualifiers: + Qualifiers, pick the record type, choose 1 to 3 qualifiers, and for each give a Field Name and a Regular Expression.

    The record type applies when its expressions match the chosen fields. For the example, field type with expression address.

  3. Header and footer: + Header & Footer, enter how many records at the start and the end to leave unmasked, Save.

    Those lines reappear unchanged in the masked output. Without this, a header such as customer_id|first_name|... would be treated as data.

Editing a record type's name and deleting a record type are in its row's Actions column. To reach the format from a rule set inventory, use the Edit File Format button.

27.7 Adding and editing fields in a format

New fields can be added only in delimited, fixed-width and JSON formats (XML and mainframe fields cannot be deleted). Click + Field on the format page.

  1. Fill in Field Name (or JSON Path), and the Formatting section (Record Type and Position).

    These are mandatory because they place the field in the line.

  2. Optionally set the Masking section: leave Enable Automatic Updates ticked if profiling may decide, or untick it to assign Domain and Algorithm yourself.

    Picking a DATESHIFT algorithm adds a date format picker.

  3. Save.

    The field appears under its record type. View, Edit and Delete are in the row's Actions.
