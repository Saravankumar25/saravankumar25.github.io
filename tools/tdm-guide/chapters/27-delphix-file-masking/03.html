A file connector tells the engine where files live. In Environments > your environment > Connectors > + Connection, choose a Source Type that starts with "File" (Delimited, Fixed Width, XML, JSON, Parquet) and then a Connection Mode.

Mounts in plain words. A mount makes a folder on a file server (shared over NFS or CIFS) appear as a folder on the engine, so the engine can read and write files there as if they were local. You register the mount first (a name, the server address and the shared path) and then pick it in the connector. Use SFTP when the files sit on a normal server you can log in to, and a mount when the share already exists.

Cloud storage. "Prefix" and "delimiter" work as in the cloud vendor's list-objects calls: the prefix (for example json/) limits which objects the engine sees. On-the-fly note. For on-the-fly file masking you need a second connector (and environment) for the target. One page says the target rule set's file path must already point to a file with the same name in the target directory, which the masked file then replaces. The masking job page says target files need not exist in advance if the file name pattern matches the source. The docs do not reconcile these two statements; test on your engine version.

Mainframe data sets (overview)

The engine can also mask IBM z/OS data sets, described by a COBOL copybook, but the data must be EBCDIC (not ASCII or UTF-8). Where a record area can be read in several ways (COBOL REDEFINES), you give redefine conditions such as [CUST-TYPE]='P' so that exactly one reading applies per record. Operators are =, <, <=, >, >= with AND, OR and NOT. Mainframe formats list a variable-length checkbox in the rule set and can be reached over FTPS or other file modes. Masking a node that has Level 88 children is not supported From docs.

27.9 The file rule set

In the environment's Rule Sets tab click Add Rule Set, choose Flat Files (the other choices are Database, Semi-Structured and Copybook), then Continue. The wizard has three steps: Details (name and a connector, filtered by rule set type), Data Files, Summary. In Data Files you add files with Add File Name (lists files the connector can see) or Add File Pattern (Java regular expressions, case sensitive, for example .*\.txt). A rule set per layout

Patterns are tempting, but files matched by one pattern all use the same format, delimiter and end-of-record. If customers_*.dat and orders_*.dat differ, make separate rule sets or separate patterns with their own properties.

27.10 Assigning algorithms to file fields

Click the rule set name to open the file inventory. Pick a file or a format in the File Format drop-down and the record types and fields appear. Edit a field with the pencil icon, as in the profiling chapter: tick or untick Enable Automatic Updates, choose Domain and Algorithm, set a date format for DATESHIFT algorithms. Profiling can fill this in for delimited, fixed-width, XML and mainframe files, and the inventory can be exported to CSV for delimited, fixed-width and XML files From docs.

Formatting properties (position, record type) are edited on the format page, not here, because the inventory belongs to the format.
