27.11 File masking jobs

A file job uses the same + Masking Job wizard as in the algorithms and masking jobs chapter, with differences you will notice at once: there is no Database Options step (no commit size, update threads, triggers or constraints), and for files the Row Limit counts delimited or fixed-width lines, mainframe records or XML elements in process per stream From docs. The choice that matters is the method.

In-Place

The engine reads the original file, masks each field, writes the result to a hidden temporary file ending .msk in the connector's location, and only after success writes it over the original. If anything fails, the original stays intact, and the user and group permissions stay the same.

On-The-Fly

Reads the source file and writes masked data straight to the target file, with no temporary file. The docs say it is significantly faster than in-place. Source and target use different connectors, so you create a separate environment and connector for the source.

For file-to-file jobs the target does not need to be a database. If your source is a database and the target a delimited file, tick Database to File Job as described earlier, make the target files in advance with the source table names, and expect binary data to be written as hex strings (the default hex prefix is \x) From docs. If a file pattern matches nothing on the source, the job still reports success although no file was masked, so check the Execution Components for the file names. Monitoring and logs work as for databases; file jobs report Bytes Masked as well as Rows Masked, and the execution summary calls them Files rather than Tables.

A ShopSphere variant: database table to masked delimited file

Suppose the test team wants a masked extract of CUSTOMERS as a file, without ever writing unmasked data to disk. That is the database-to-delimited-file on-the-fly case:

  1. Create the target connector and an empty target file named like the source table (for example CUSTOMERS) in the target directory.

    The docs require the target file to exist and match the table name for this case.

  2. Create a delimited file rule set for the target file, with a format whose field names are the table's column names, and assign algorithms to those fields.

    The Create Masking Job screenshot with the "Database to File job" checkbox (in the algorithms and masking jobs chapter) shows a delimited rule set chosen for such a job. The documentation excerpt I had does not spell out how fields are matched to table columns, so confirm this on your engine version.

  3. Create the masking job: On-The-Fly, tick Database to File Job, choose that rule set and the source environment and database connector.

    Without the tick, only file connectors appear in the source list.

  4. Run it and open the output file.

    Masked rows appear as delimited lines; binary columns, if any, appear as hex strings.

27.12 JSON, XML, Parquet and whole-file masking (brief)

These are covered by the same connector, format, rule set and job chain, with a path language instead of positions.

TypeHow fields are namedWhat the format file shows
JSONJSON Path: $[*]['First_Name'] for a list of objects, $['First_Name'] for one objectOnly fields you want to mask need to appear (values may be null placeholders); one record per structure is enough
XMLXPath: /Person/First_Name; attributes use "@" (for example /employee/@name)A document with empty tags or dummy values; the root element is required
ParquetColumn path: First_Name; nested Location/Address; lists Emails/list/elementA schema-only file or a .txt or .fmt schema listing; binary columnar format

Whole-file masking. Sometimes a file should go to one algorithm in one piece (a free-text document, say). Create a fixed-width connector and a format with exactly one field of length 0, tick Mask whole file in Edit Selected for the data file (End of Record then disappears), and assign an extended algorithm to the one field. The default limit is 200 MB per file, adjustable with the application setting Whole File Masking Max File Size In MB; Add Record Types, Add Fields and Delete are disabled for such formats From docs.
