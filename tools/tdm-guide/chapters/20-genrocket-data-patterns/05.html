20.9 Enforcing data type and size

20.9.1 In plain words

General concept Every database column has a type and a size. A first_name VARCHAR(5) column holds at most five characters. An INT column holds whole numbers up to about two billion. If your generator produces "Maximiliano" for that first-name column, the insert fails, and a hundred rows of perfectly good data are lost because one name was too long.

For positive data, generated values must always fit the column, so loads never fail; GenRocket does this with a switch called Enforce Type/Limit. For negative data (the long-name edge case in section 20.6.5) you deliberately break the size.

20.9.2 Enforce Type/Limit

From docs The page "How to Enforce Data Type and Size in Generated Data" explains the option (link):

  • Value limits are enforced automatically when you import a DDL (database table definition) or an XTS file (GenRocket's extracted table schema). The option is switched on for every generator assigned during such an import.
  • It is available on every generator and can be set on any individual generator in a domain.
  • Use it "whenever you want the generated data to be within a defined data type and size".
  • When on, it limits output to the Type and Size parameters of the attribute.

The page's example: NameGen with Enforce Type/Limit on, Type varchar and Size 5. First names in the Preview pane are limited to 5 characters.

Integer limits the page lists for Enforce Type/Limit
Data typeLargest value enforced

These are boundary values in their own right: for a smallint column, 32767 is the maximum and 32768 is the "just above maximum" negative test.

20.9.3 Setting it by hand

For a manually built domain: open the attribute, type a data type (varchar, int, float, decimal) in Type and the limit in Size, click Save, then tick Enforce Type/Limit in the generator form and save the generator. The Preview pane then shows values within the size.

Turning it off for edge cases

Because it is on by default for imported models, a generator will not produce the too-long name a negative test wants. Switch it off on that generator, or use a separate generator for the edge value, and check Preview.

20.9.4 Decimal places and number formatting

Money needs fixed decimal places: 49.9 and 49.90 are different text, and a DECIMAL(8,2) column expects two.

From docs NumberFormatGen formats a referenced number: pad with leading zeros, fix the number of decimal places, fix the number of digits, add commas, include a sign. Parameters (NumberFormatGen):

  • reference*: the attribute (or linked generator) to format. It should produce a floating-point number.
  • decimalFormat*: a pattern. The page's sample: 123456.789 with ###.## gives 123456.79.
  • includeSign*, includeDecimal* and padLength*: whether a sign and the decimal point appear, and how many zeros to pad on the left.

The page links NumberFormatGen to RangeDecimalGen and RandomDecimalGen, which supply the decimal number. Those two have no separate pages; from the page's screenshots, RangeDecimalGen shows parameters startRange, endRange, decimalFormat, jumpAmount, waitAmount and sortOrder, and RandomDecimalGen shows startRange, endRange, decimalFormat and seed.

For the typical partition of total_amount use RandomDecimalGen from 1 to 5000 with a seed; by analogy with the screenshot's #0.0000, two decimals would be #0.00 (check in Preview). Boundary rows come from the boundary lab.

20.10 Dates and times

20.10.1 In plain words

General concept Dates breed bugs: a birth date that makes someone 17 versus 18, an order dated 29 February, a timestamp at midnight, month-first versus day-first formats. Date test data needs three things: a format (how the date is written), a range (earliest and latest) and a pattern (sequential, random, or specific edge dates).

20.10.2 FlexibleDateRangeGen

From docs GenRocket automatically picks FlexibleDateRangeGen for attributes whose imported data type is "date" or "time" (How are Generators Assigned). It generates dates from a start date, moving by a range and a jump (FlexibleDateRangeGen).

FlexibleDateRangeGen parameters as documented
ParameterMeaning
format*The date format for the start date and the output. Default yyyy-MM-dd. Others: MM/dd/yy, MM-dd-yy, yyyy-MM-dd HH:mm:ss.
startDateThe anchor date. Empty means the current date.
startRange*, endRange*Integers: how far forward (positive) or backward (negative) to move from the start date. Zero means no change. An error occurs if startRange is more than endRange.
initialJump*How much to jump before the first value (Year, Month, Week, Day or Hour).
jumpAmount*How much to jump by for each value.
nextBy*Which part of the date moves: Year, Month, Day, Hour, Minute, Second or Millisecond.
waitAmount*Rows to repeat a date before moving on.
randomize*Sequential (false) or random (true) within the range.
seed, randomizeMonthDay*, excludeRepeatable random dates; whether month and day are random; values to skip.

The page's first example: startDate 01-01-1970, startRange 0, endRange 4, initialJump 0, jumpAmount 10, nextBy Year, randomize false and randomizeMonthDay None. The first record is 01-01-1970 and the year grows by 10 each record: 1970, 1980, 1990, 2000, then the pattern restarts at 1970 on the fifth record.

Check the direction yourself

Example 2 contradicts itself: its jumpBy line says the year increases, but the title, records and screenshot go 1965 down to 1961. In the examples a cycle holds endRange minus startRange values (0 to 4 gives four dates). Change one parameter at a time and read the Preview pane.

20.10.3 Date formats

From docs The "Date and Time format" page lists the pattern letters (link). The ones you will use most:

Year is y, month M, day d, hour H (0 to 23) or h (1 to 12), minute m, second s and am/pm a.

Capital M is month and lower-case m is minute, so yyyy-mm-dd prints the minute where you wanted the month. Attributes also have a Date Format parameter that "defines the Date Format if the Attribute is generating a Date".

20.10.4 DateDeltaGen: the gap between two dates

From docs DateDeltaGen "computes the delta between two dates", in days, months, years or hours. Parameters: conversion*, formatOne*, formatTwo*, dateRefOne*, dateRefTwo*. The page's example links two FlexibleDateRangeGen generators and subtracts their dates (DateDeltaGen).

That gives a way to check an age rule in the data itself: generate a date_of_birth, hold a reference date in a ConstantGen (the ConstantGen page lists dates such as an effective date as a valid constant), and use DateDeltaGen with conversion years between them. The pages do not say how partial years are rounded, so verify the 17 and 18 rows by eye.

Worked example: the 17 versus 18 rows

For the boundary rows, a ListGen with setLoop True holds 2008-01-02, 2008-01-01, 2007-12-31 and 1990-04-12, the four rows of the age table in section 20.8.1. For a realistic spread of adult birth dates use FlexibleDateRangeGen with nextBy Year, randomize true and a seed, and check the range cannot produce under-18 dates unless you want them.
