20.3 Sequential data

20.3.1 In plain words

General concept Sequential data follows a fixed, predictable order: 1, 2, 3, 4, like numbered tickets at a bakery counter.

Testers want sequential data in three places:

  • Primary keys. A primary key must be unique, so counting up is the simplest safe pattern. ShopSphere's customer_id values 1001, 1002, 1003 are sequential.
  • Numbered records. Order numbers such as ORD-1001, ORD-1002, where you want to look at row 5 and know exactly what should be there.
  • Predictable walks. A list of statuses walked in order (Pending, Shipped, Delivered) so a test can assume which row has which status.

Sequential data is easy to read when a test fails, but looks nothing like real life, so mix it with random data for other columns.

20.3.2 RangeGen: counting up (and down)

From docs The generator for counting is RangeGen. The help page says it "produces an increasing value from startRange to endRange", or to long.MAX_VALUE when no end range is given, and that "once the endRange has been reached, the value is reset to the startRange" (RangeGen help page). The page also notes it can be set to start at a number other than 1, for example to continue a database's primary keys. From video The 2020 webinar demo shows the pattern live: the id counts up from 1,000, and changing the jump from 1 to 3 makes the sequence step by three (section 18.6.11).

The help page shows five worked examples. Four of them follow, each with the official screenshots of the parameters and the preview.

Start at a chosen value. Setting startRange to 500 makes the first row 500, then 501, 502 and so on.

Jump and wait. With startRange 0, endRange 100 and jumpAmount 5 the values are 0, 5, 10, 15 and so on. Raising waitAmount to 3 makes each value repeat three times (0, 0, 0, 5, 5, 5) before the jump, the pattern for one parent value repeated across several child rows.

Count down through negatives. Set startRange -1, endRange -100 and sortOrder descending.

Direction and range must agree

If you give a descending order a positive end range, GenRocket stops you. The help page names the error "startRange cannot be less than or equal to endRange" and gives two fixes: change endRange to a negative value, or change sortOrder to ascending. 20.3.3 Other ways to get sequential values

RangeGen is the main tool, but the documentation shows several more sequential patterns.

  • The domain id. From docs When a domain is created or imported it automatically gets an id attribute that "generates a unique ID for each test data record" (Attributes Overview). For many tests that is the primary key and you need do nothing.
  • RangeConstantGen. The string-generators list describes it as an increasing value "similar to the RangeGen" with an optional prefix and suffix. With range 1 to 5 and prefix test the output is test1 to test5. The StringRemoveGen page confirms the parameter names startRange and prefix for it. For ShopSphere, a prefix of ORD- and start 1001 gives ORD-1001, ORD-1002 and so on.
  • ListGen in order. From docs ListGen "generates items in a provided list in sequential or random order". Its random parameter defaults to False, so the list is walked in order. Its example sets waitAmount to 5 so each of Pending, Shipped and Delivered repeats for five rows before moving on (ListGen).
  • PhoneNumberGen. The page says it "generates phone numbers in a sequence (100-1000, 100-1001, ..., 999-9999)", with two optional parameters: areaCode (the three-digit area code placed in front) and prefix (the starting prefix, from which the number increases). It points to RandomPhoneNumberGen for random numbers.

20.3.4 Continuing after existing data

From docs Sometimes the target database already has rows, and new primary keys must start after the largest existing one. The help centre shows a linked-generator recipe (primary key values after the max value):

  1. Add QueryOnceGen to the id attribute.

    It runs one query before generating. Set resourceName to the JDBC resource, query to select max(id) + 1 from <tableName> and give sampleValue (the page uses 5001) so the Preview pane has something to show.

    gen1 holds "the next free id".

  2. Add RangeGen after it.

    For startRange, double-click the field and choose the Attribute Generator tab, then pick gen1 (it is written #{self.gen1}).

    New ids begin after the largest existing id, so inserts will not collide with existing rows.

RangeGen can reference QueryOnceGen only because QueryOnceGen sits to its left, a rule covered in section 20.6.

Gotcha: a sequence that wraps is not unique

RangeGen goes back to startRange when it reaches endRange. If you set a small endRange on a primary key and generate more rows than the range holds, you create duplicate keys. Leave endRange empty for ids, or make sure the loop count is no larger than the range.

20.4 Random data and repeatable randomness

20.4.1 In plain words

General concept Random data is data picked without a visible order. Random data is what makes a generated customer list look real: different names, ages and cities.

Random data has one practical problem. If a test fails today with a random customer, and tomorrow's run creates different customers, you cannot reproduce the failure. The fix is the seed: a starting number for the random picker. The same seed gives the same "random" sequence every time. Random but repeatable is the best of both.

20.4.2 RandomGen: a random number in a range

From docs RandomGen "randomly generates a number within a range"; the page's own example is random ages between 18 and 65 (RandomGen).

RandomGen parameters as documented
ParameterMeaning
startRange*The smallest value that can be produced.
endRange*The largest value that can be produced.
uniqueLimitHow many times a given value may be produced. Empty means no limit. 1 means each value appears at most once; 10 means each value can appear ten times. It does not apply to dynamic start and end ranges that change per row.
seedMakes the same random data come out every run.

The page's second example limits repeats: numbers 1 to 10, uniqueLimit 2, and a domain loop count of 15 so the possible values are not used up. Each number appears at most twice.

The error you get when uniqueness runs out

With uniqueLimit 1, range 1 to 20 and a loop count of 20, the page reports "Exhausted attempts to find the next valid random value from range of 1 to 20". The fixes it lists: raise the loop count, widen endRange or raise uniqueLimit. The rule of thumb is that rows asked for must be no more than (range size times uniqueLimit). The same Java memory exhaustion can appear for very large unique sets: the troubleshooting page for "GC overhead limit exceeded" lists "generator parameters that limit the amount of data, such as a unique limit" as a cause (that error page).

20.4.3 Random names, lists and strings

  • NameGen. Generates first, last, male or female names (nameType), cased as capitalize, upperCase or lowerCase (caseType), in random, ascending or descending order (sortOrder), with an optional seed and a waitAmount. Its pool (1,000 male, 3,000 female and 10,000 last names) gives 40,000,000 combinations.
  • ListGen. Set random to True to pick from a fixed list in random order (the page example picks one of five colours). Add unique True to use each list value only once; then the loop count must not exceed the number of values, or GenRocket throws an exception. ListGen supports up to 15 list items; for bigger lists the page recommends ListCSVV2Gen.
  • RandomStringGen. Random text of a given length and stringType (letters, numbers, lettersAndNumbers, specialCharacters, ASCIICharacters or allCharacters), with caseType, seed, unique, include and exclude. The help page lists "test boundary conditions or invalid characters" and "filling a notes field with random strings to test character limits" among its uses. Its promo-code example links ConstantGen (PROMO), RandomStringGen (6 unique digits) and ConcatGen.

20.4.4 Seeding: random, but the same every time

From docs The help page "What is Seeding?" defines seeding as generating "the same set of random data for the same value of a seed". It says a seed can be entered in several places in GenRocket, including the domain's Global Seed variable and the generator's own seed parameter (What is Seeding?). The page's example uses two attributes, number1 and number2, both RandomGen from 1 to 25:

  • No seed on number1: a different set of numbers every time the data is generated.
  • Seed 1 on number1: one fixed set, the same every run.
  • Seed 1 on number2 too, same configuration: number2 gets the same set as number1, so use different seeds for columns that should look independent.
  • Seed 2 on number2: a different fixed set.

From video The 2020 demo shows the problem live. With no seed, the first name, last name and middle initial change every time the preview refreshes. The CTO explains that a global seed, which can be assigned to many generators, makes the same random data appear every time for the same seed value. That matches the docs' domain Global Seed and generator seed.

Why seeding matters for a TDM engineer

Without a seed, "random" test data differs each run, so a failing test is a ghost. With a fixed seed, a regression suite sees identical data every night, and a failure can be replayed on a developer's laptop. Seed attributes you want repeatable. Leave the seed empty on attributes where you want fresh variety each run, such as a load test.
