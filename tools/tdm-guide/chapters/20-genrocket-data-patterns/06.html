20.12 Lab: a realistic orders mix

Lab: 100 orders that combine four patterns

Goal: one domain that mixes sequential, seeded random, weighted and null data, so you see how patterns stack on different attributes of the same row. Project, domain, receiver and scenario steps are the same as in the 50-record lab, so this lab only lists what is different. Generator names and parameters are the ones documented above. The two-decimal decimalFormat is by analogy with a screenshot, so check it in Preview.

  1. Create a domain OrderMix and set its loopCount to 100.

    Domain Variables, pencil icon on global.OrderMix.loopCount, Save.

    The variable shows 100.

  2. Attribute orderId: RangeGen from 5001.

    Sequential and unique, so it works as a key. Leave endRange empty so it never wraps.

    Preview: 5001, 5002, 5003 ...

  3. Attribute totalAmount: RandomDecimalGen 1 to 5000 with a seed.

    Realistic variety, repeatable because of the seed. Format to two decimals.

    Preview: amounts such as 1834.27. Regenerating gives the same list.

  4. Attribute status: MultiWeightGen Delivered 70, Shipped 15, Pending 10, Cancelled 5, exactPercentage True.

    Exact shares let you check the file by counting.

    In the output, 70, 15, 10 and 5 rows respectively.

  5. Attribute email: EmailGen with % Null 10.

    EmailGen (assigned automatically to names containing "email") needs prefix, reference, suffix and extension. Reference orderId so each address is unique. Set the Null Value as described in 20.7.2.

    Roughly one row in ten has a null email.

  6. Add a DelimitedFileReceiver, scenario and run.

    Set nullValue to what your downstream loader expects.

    100 data rows. Count the statuses, check that orderId runs 5001 to 5100, and count empty emails.

Show what to check
  • Row count 100 plus one header line.
  • Status counts exactly 70/15/10/5 because exactPercentage is True. If counts drift, check that setting.
  • Null email count near 10 (the page does not promise an exact count for % Null).
  • Run twice: totalAmount should be identical both times because of the seed, while the null positions may or may not be, depending on whether you also seeded that part. Note which behaviour you see.

20.14 Recap

Recap
  • Test data needs patterns: typical data for positive tests, tricky data (boundary, edge, null) for negative tests.
  • Sequential: RangeGen (startRange, jumpAmount, waitAmount), the domain id, ListGen in order, PhoneNumberGen. A range that wraps is not unique.
  • Random: RandomGen, NameGen, ListGen and RandomStringGen; a seed makes random data repeatable, and two attributes with the same seed and settings repeat each other.
  • Weights: WeightGen for two-way splits, MultiWeightGen with exactPercentage True for exact shares.
  • Linked and conditional generators run left to right and may only reference what is to their left (and attributes above them). EvalCaseGen handles if/else; EdgeCaseGen mixes in edge values by cycle, percentage or condition.
  • Null and blank: attribute % Null and Null Value, NullGen, ConstantGen with #{BLANK} or #{EMPTY}, Output Condition, and the receiver's nullValue.
  • Boundary value analysis: test just below, on and just above each limit, plus one typical value. In GenRocket use exact lists (ListGen with setLoop True) for boundaries.
  • Enforce Type/Limit keeps values inside the column; NumberFormatGen fixes decimals; FlexibleDateRangeGen and DateDeltaGen cover dates. Verify uncertain behaviour in Preview.
