17.6.5 Setting it up: the shape of the steps

The outline of the Windows setup follows; folder paths and exact variable names belong to the vendor page for your system.

  1. Check the prerequisites.

    An active user account, the cloud address reachable on port 443, admin rights, and Java installed.

    What you should see: java -version prints a supported version.

  2. Download the runtime zip from the web platform (Options menu) and extract it into your home directory as a folder named genrocket.

    The page warns against a nested folder such as genrocket\genrocket-3.5.x.

    What you should see: a genrocket folder with bin and lib inside.

  3. Set the environment variables, open a new terminal and run genrocket once.

    The first run downloads the other jars into lib and creates the hidden .genrocket folder.

    What you should see: no error. "genrocket is not a recognized command" means the folder name, home variable or PATH is wrong.

  4. Download your user profile into .genrocket and fill in your organisation resources.

    Resources hold folder paths for home, JDBC configuration and output (enter N/A for JDBC if you connect to no database).

    What you should see: a .grp profile file in .genrocket and your own paths in the Resources pane.

From docs Typing genrocket alone, or genrocket -h, prints the runtime's command-line options for your version.

17.6.6 Updates, Docker and Jenkins at overview level

Updates. A full runtime update replaces the whole genrocket folder; a jar-only update is done from the command line. Release notes say which is needed.

Docker. GenRocket provides a Docker image you download from the web platform and load with docker load. A container forgets everything when it stops, so you mount host folders for the runtime, scenarios, configuration files, the .genrocket profile folder and the output.

Jenkins (continuous integration). Jenkins is a popular tool that runs build and test jobs automatically. The Windows and Mac/Linux Jenkins pages run a scenario as a build step. The outline: install the runtime on the Jenkins server and set the variables where Jenkins reads them (builds do not see your personal environment); register the server in the web platform and download its Server Profile into the server's .genrocket folder (no person is logged in on a build server); then create a Freestyle job whose build step first runs bare genrocket to prove Jenkins can find it, and then genrocket -d -r SCENARIO_NAME.grs. You should see a SUCCESS message in the console and your files in the output folder. Section 19.4.10 shows how the 2020 webinar combines this with Selenium tests.

The CI/CD page adds two ways to trigger generation from a pipeline: a shell or batch command running the runtime, or a REST request to a GenRocket server component. It also describes Java and REST APIs that let a pipeline create or modify a scenario in real time, for example to change a loop count (how many rows) per test.

Not covered here

Linux and Mac setup, the multi-user server, G-Repository administration and API method details are separate topics in the help centre and are not described here.

17.7 The web platform and the Project Dashboard

From docs You reach the web platform with a link, a user name and a temporary password from a welcome email. The first-login page lists password rules and, after you accept the licence agreement, may ask you to change the temporary password. Organisations that use single sign-on or multi-factor authentication may log in differently; ask your administrator.

The docs describe those three panes this way: Projects lists and manages the organisation's test data projects; Queue Status shows tasks waiting to run, such as a project deletion or a data import (a Refresh button updates it); Resources holds organisation resources, which are named variables whose value differs per user (typically a folder path), so one scenario works on everyone's computer.

Select a project and more panes appear. This one screen is where most work happens. The complete screen, with a small demo project loaded, is below.

The page also lists common icons. An open padlock locks an item: locked items cannot be deleted, and the lock stops changes made higher up from flowing down (you will meet locks again in the receivers and scenarios chapter). The main menu bar offers Options (downloads such as the runtime), Management, Presets and Help.

Reading order for the Project Dashboard

Work left to right, top to bottom: pick a project, pick a version, look at its domains, look at its scenarios. That is also the order in which you build things.
