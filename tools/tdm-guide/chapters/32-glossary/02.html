Data domain profile (Informatica)

Data generation (Informatica)

Data Integration Service (Informatica)
The application service that performs discovery profiles and data coverage tasks. Section 10.4
Data integrity for subset (Informatica)
A plan setting for how far subsetting follows relationships: Transactional (default), Referential Only, One-way or Two-way. Section 13.6
Data pack (Informatica)

Data pattern and metadata pattern (Informatica)

Data set (Informatica)
A named collection of tables in the test data warehouse; storing it again creates a new version. Section 16.16
Data Validation Option (Informatica)
A separate Informatica solution used with PowerCenter to check that target data is accurate. Section 10.3
Dictionary (Informatica)
A file or table of ready-made values that a rule picks from; an authorised user must add it to TDM first. Section 15.9
Driving table (Informatica)
The table chosen as an entity's starting point. The syllabus says "driver table". Section 13.1
Effective Dates technique (Informatica)
Fills start and end date columns so periods follow one another without overlap. Section 15.9
Encryption masking (Informatica)
Standard (AES, CRC, MD5) or format-preserving encryption; the latter can be decrypted with the same pass phrase. Section 14.6
Entity (Informatica)
A driving table plus all tables related to it by constraints; the unit copied to a subset. Section 13.4
Entity profile (Informatica)
A profile that finds possible entities by comparing column names across source tables. Section 12.6
Exception handling (Informatica)
Per-rule settings for nulls, blanks and errors, plus optional pre- and post-processing expressions. Section 14.5
Exception test data (Informatica)
Deliberate nulls and invalid values, set as percentages, mixed into generated output. Section 15.8
Expression Builder (Informatica)
A dialog for building a formula by picking functions and columns. Section 11.8
Expression masking (Informatica)
Applies a formula built in the Expression Builder; repeatable output needs a storage table. Section 14.6
Generation rule (Informatica)
A saved recipe for one kind of value: a technique plus its parameters. Section 15.1
Global rule (Informatica)
A named rule created once in Policies and reusable in every project. Section 15.4
Group (Informatica)
Unrelated tables, or tables to copy unfiltered, added to a plan as they are. Section 13.5
ilmcmd, tdwcmd, tdwquery (Informatica)
Command-line programs: ilmcmd runs some TDM tasks, tdwcmd lists warehouse details, tdwquery runs SELECT queries on a data set. Section 16.14
Impacted Objects dialog (Informatica)
A warning listing what breaks when you change or delete something already in use. Section 11.1
Informatica Administrator
The web client where a domain administrator manages application services, users and groups. Section 10.4
Informatica domain
The family of Informatica services installed and managed together, with a shared set of users. Not a data domain. Section 10.1
Job (Informatica)
Something TDM runs, such as a profile, workflow generation or workflow run, listed in Monitor with a state like In Queue, Running, Success, Error or Terminated. Section 16.11
Key masking (Informatica)
Deterministic masking from input, rule and seed; give key columns in both tables the same seed. Section 14.6
Logical key or constraint (Informatica)
A key relationship defined only inside TDM; the source tables are not updated. Section 12.1
Major / minor constraint (Informatica)
A foreign-key severity: major pulls rows both ways, minor only child to parent. Section 13.6
Mapplet (Informatica)
A reusable group of PowerCenter transformations; TDM can import one as a custom masking or generation rule. Section 14.9
Masking rule (Informatica)
A technique plus its parameters, saved under a name. Section 14.1
Masking technique (Informatica)
The logic that replaces a value, such as substitution or shuffle. Section 14.6
Model repository (Informatica)
Holds table metadata for discovery profiles and connection information. Section 10.4
Monitor (Informatica)
The view for checking job status, stopping jobs and reading logs. Section 16.11
Nullification (Informatica)
Replaces the value with NULL. The strongest privacy result, but the target column must allow NULL. Section 14.6
Override (Informatica)
Letting whoever assigns a rule change its parameters for one column. Overridden seeds on matching columns break the match. Section 14.3
Parameter (Informatica)
A named placeholder whose value you supply at run time, so one plan serves many runs. Section 16.1
Plan (Informatica)
The saved recipe of one operation: components, source and target connections, settings. It does nothing until a workflow is generated and run. Section 16.2
Policy (Informatica)

Policy pack (Informatica)

PowerCenter

PowerCenter Integration Service (Informatica)

Profile (Informatica)

Profiling warehouse (Informatica)

Project (Informatica)

Repository (Informatica)

Reset (Informatica)

Residual tables (Informatica)
Tables not yet in any group or entity; tick them into a group to cover the whole source. Section 13.5
Restricted column (Informatica)
A column property that stops the value being written to the target. Section 4.6
Row Count Report (Informatica)
Shows the tables in a workflow run and how many rows were affected. Section 16.12
Rule (Informatica)
The logic that masks a value or generates test data: a technique plus parameters. Section 4.8
Rule Simulator (Informatica)
A built-in preview showing original beside masked values for a standard rule. Section 14.3
Seed (Informatica)
A start number, 1 to 999 and default 1, giving repeatable output. Note: sources differ; one guide table says 1,000. Section 14.5
Sensitive flag (Informatica)

Sensitivity level (Informatica)

Sequence technique (Informatica)
Generates ordered numbers or dates from a start value and increment. Section 15.9
Set of Values technique (Informatica)

Built-in techniques that keep each format valid, for example a card number keeps a valid checksum. Section 14.6
Staging connection (Informatica)
A database connection for temporary working tables; recommended as the source for cyclic subsets. Section 16.5
Standard rule (Informatica)
A built-in technique with parameters: one technique, one input column and one output column. Section 14.3
Storage connection (Informatica)
A database holding storage tables for repeatable substitution and expression masking. Section 16.5
Substitution masking (Informatica)
Replaces a value with similar unrelated data from a dictionary; unique substitution fails if the dictionary is too small. Section 14.6
Template (Informatica)
An optional container for entities and groups; the guide gives little detail. Section 13.5
Test Data Manager (Informatica)
The web client you work in; the name is also used for the whole product. Section 10.1
Test Data Manager Service (Informatica)
Creates and manages the TDM repository and runs Test Data Manager. Section 10.4
Test Data Warehouse (Informatica)
A central store for versions of test data, so teams can save and restore a known-good state. Section 16.15
Uniqueness percentage (Informatica)
The share of values in a column that are unique; 100 means no duplicates. Section 12.1
Value cascade (Informatica)
Gives similar columns not linked by a key the same masked value, via a chosen driving column. Section 14.4
Version and tag (Informatica)
Each re-store of a data set makes a new version; tags are comma-free words used to search data sets. Section 16.16
View (Informatica)
One of the main Test Data Manager screens, chosen from the tab bar. Section 11.1
Workflow (Informatica)
The runnable job TDM generates from a plan; PowerCenter runs it. Section 10.1

A receiver setting for one attribute, such as columnName or include. Section 19.1

Domain Dashboard (GenRocket)
The screen where you work on one domain's attributes, variables, receivers and scenarios. Section 18.2
Domain (GenRocket)
One "thing" you want data for. For a database it is a table; it can also be a file, message, JSON or XML document. Section 17.3

Sets parents and siblings for many domains at once, with a diagram that redraws as you click. Section 18.3

EvalCaseGen (GenRocket)

FixedFileReceiver (GenRocket)

G-Case / Test Data Case (GenRocket)
Changes components inside a scenario so one scenario gives many permutations for different test cases. Section 7.11

GenericSQLInsertReceiver (GenRocket)

GenRocket Runtime (GenRocket)
Java programs on your own machine that read a downloaded scenario and generate data inside your firewall. Section 17.6
G-Portal (GenRocket)
A self-service platform where requesters search for, request and download test data. Section 7.11
G-Repository (GenRocket)
The component that keeps scenarios and configuration files in sync across a company's machines. Section 17.5
.grs file (GenRocket)
The downloaded, encrypted scenario file you run with genrocket -r. Section 19.1
Import from DDL / XTS (GenRocket)
Two ways to create many domains from a schema: paste CREATE TABLE text, or extract structure from a live database. Section 18.2
Linked generators (GenRocket)
Several generators in one attribute, run left to right; later ones can use earlier values. Section 18.6
ListGen (GenRocket)
Picks from a fixed list of values, in order or at random. Section 20.5
Loop count (GenRocket)
How many rows a domain generates. A child's count is per parent row. Section 19.4
Masking receivers (GenRocket)
Receivers that take an existing file and write a new one with targeted values replaced. Section 19.3
Master project (GenRocket)
A project option for sharing master domains with other projects. Section 17.8
Model, Design, Deploy, Manage (GenRocket)
The four work phases of GenRocket's methodology: import the model, design the data, generate and deliver it, manage versions. Section 17.4
Offline certificate (GenRocket)
A file letting the runtime run scenarios without internet; organisation-specific and valid 24 hours. Section 17.6
Organization resource (GenRocket)
A named folder setting, such as resource.output.directory, each user fills with their own path. Section 19.2
Output format (GenRocket)
The shape of the result: delimited, fixed-width, JSON, XML, Excel, SQL statements and many more. Section 19.1

PermutationGen (GenRocket)

Preview (GenRocket)
Sample generated values shown in the web platform so you can check before downloading. Section 18.1
Primary attribute (GenRocket)
The attribute marked as the key, which children refer to. Section 18.1

The primary domain is the one a scenario is built for; the root is the first parent at the top of the chain. Section 19.1
Project and project version (GenRocket)
A project holds the data model for one application or database; a version is one release's copy of it. Section 17.8
Project type (GenRocket)
Standard (default), Micro (domain-limited, such as files) or IPM (in-place masking of databases). Section 17.8
QueryOnceGen (GenRocket)
A query generator that reads real data from a database once, for example the current maximum id. Section 18.6
Quick Scenario (GenRocket)
Builds a scenario named after a domain, adding its parents and siblings for valid keys. Section 19.4
RangeGen / RandomGen (GenRocket)
Number generators: RangeGen counts up (or down); RandomGen picks a random number in a range. Section 18.6
Receiver (GenRocket)
The component that turns raw generated values into a usable output: file, SQL, message and more. Section 19.2
Receiver parameter (GenRocket)
A setting for the whole receiver, such as where to write; a star marks required ones. Section 19.1
Reference parameter (GenRocket)
A parameter value pointing at another attribute or generator, so one value is built from others. Section 21.1
ReferenceGen / ProxyReferenceGen (GenRocket)
The foreign-key pair: the proxy marks "a parent key goes here" on the domain; the real ReferenceGen replaces it in a scenario. Section 18.6
Scenario chain (GenRocket)
Linked scenarios run in order by one command; a chain set links chains. Section 19.4
Scenario domain (GenRocket)
A scenario's copy of a template domain; template changes flow down unless locked. Section 18.1
Scenario (GenRocket)
A saved instruction sheet: which domains to generate, how many rows, in what order. Running it makes the data. Section 19.4

A starting number for random generators; the same seed gives the same "random" data. Every domain has a seed variable. Section 18.6

Pairs that build nested JSON or XML: each domain writes segments, a merge receiver combines them. Section 19.3
SimplePatternGen (GenRocket)

SQLFileInsertReceiver (GenRocket)

Template domain (GenRocket)

Test Data Engineer (GenRocket)

Web platform (GenRocket)
GenRocket's cloud web application, where you model and design. Also called GenRocket Cloud. Section 17.1

XTS (GenRocket)
Extract Table Schema: a runtime option that writes a live database's structure, not data, to an encrypted file. Section 18.2

32.6 Delphix

Algorithm (Delphix)
The recipe that replaces a real value with a safe one. Profiling only chooses it; the masking job runs it. Section 25.1
Algorithm framework (Delphix)
A kind of algorithm you configure into instances, such as Secure Lookup or Segment Mapping. Section 26.1
Algorithm instance (Delphix)
A named framework plus settings, such as dlpx-core:FirstName. This is what you assign to a column. Section 26.1
Algorithm key (Delphix)
A secret value inside most algorithms; changing it changes every output. Section 26.1
Algorithm syncability (Delphix)
Copying algorithms between engines so both mask alike. Non-deterministic ones cannot be synced. Section 24.9
Application (Delphix)
A tag naming the system whose data you manage; create one before an environment. Section 23.2
ASDD profiler (Delphix)
Automated Sensitive Data Discovery, the current profiler, using classifiers instead of the legacy search expressions. Section 25.1
ASDD Standard (Delphix)
The recommended built-in profile set, with path, type, regex and list classifiers. Section 25.5
Assignment threshold (Delphix)
The minimum confidence before the profiler writes a domain and algorithm into the inventory. Section 25.1
Async Task (Delphix)
A background task whose ID you can search under Monitor, Async Tasks. Section 22.4
Character Mapping (Delphix)
A keyed one-to-one swap of characters within groups you define; unlisted characters stay. Suits key columns. Section 26.4
Checklist (Delphix)
An action checking that every table in a rule set has a primary key, an indexed identity column or a logical key. Section 24.8
Classifier (Delphix)
One recognition rule tied to one domain, such as a column name that looks like ssn. Section 25.1
Classifier framework (Delphix)
A kind of classifier: PATH (table and column name), TYPE (data type and length), REGEX (data) or LIST (values in a list). Section 4.7
Collision (Delphix)
Two different real values masked to the same fake value. Section 22.7
Confidence (Delphix)
A 0 to 100 score for how sure the profiler is about a match. Section 25.1
Connector (Delphix)
Saved details the engine uses to reach one database or set of files. Section 23.3
Containerized engine (Delphix)
The engine run as a Kubernetes pod of three containers; meant for ephemeral use, and without FTP file masking. Section 22.8
Continuous Compliance engine (Delphix)
The product that discovers sensitive data and masks it; also called the masking engine or Compliance Engine. Section 22.1
Continuous Data engine (Delphix)
The virtualization product that creates VDBs; never run it in the same machine as the masking engine. Section 23.9
Copybook (Delphix)
A rule set type for mainframe data sets described by a copybook. Section 24.4
Date Shift (Delphix)
Moves a date within a range, never back onto itself. Fixed shifts are deterministic; variable ones are not syncable. Section 26.9
Dependent Date Shift (Delphix)
Masks two related dates together, keeping their order and interval. Section 26.4
Domain (Delphix)
A named kind of sensitive data, such as FIRST_NAME, with exactly one default masking algorithm. Section 22.1
dSource (Delphix)
The engine's compressed copy of a source database from which VDBs are made. Section 23.9
Encoding (Delphix)
How characters become bytes. ASCII and UTF-8 for most file types; mainframe data must be EBCDIC. Section 27.3
End-of-record (Delphix)
The characters ending a line: LF on Linux, CR+LF on Windows. Section 27.1
Environment (Delphix)
A folder-like container inside an application holding connectors, rule sets and jobs. Its purpose is Mask or Tokenize/Re-Identify. Section 23.2
Extended connector (Delphix)
A connector on an uploaded JDBC driver, for databases not supported natively. Section 23.1
File connector and file rule set (Delphix)
The connector says where files are; the rule set lists which files or name patterns and which format each uses. Section 27.1
File format (Delphix)
A small uploaded description of a file's field names (and lengths for fixed width). Metadata only. Section 27.5
Free Text Redaction (Delphix)
Blanks sensitive words and patterns inside notes columns; needs expertise to configure. Section 6.4
Identity column (Delphix)
A column that numbers rows automatically; the engine can use one as the key or add a temporary one. Section 24.1
In-place / on-the-fly (Delphix)
In-place changes data where it sits; on-the-fly reads a source and writes masked data to a target. Section 26.11
Inventory (Delphix)
The table of every column or field in a rule set with its domain and algorithm: profiler output, masking input. Section 25.1
JDBC (Delphix)
Java Database Connectivity. The engine uses a JDBC driver per database and a JDBC URL to say where to connect. Section 23.1
Job (Delphix)
A saved runnable task: profiling, masking, tokenization or re-identification. Section 22.1
Logical key (Delphix)
A unique, non-null column (or columns) you tell Delphix to treat as the row identifier; the database is unchanged. Section 24.7
Lookup file (Delphix)
A text file with one replacement value per line; the algorithm picks a line from the input. Section 26.1
Mapping (Delphix)
You supply replacement values; each input gets a distinct output, stored encrypted. Needs enough values. Section 26.9
Masked VDB (Delphix)
A VDB whose data was masked by a masking job during provisioning; it cannot be unmasked. Section 23.9
Masking engine (Delphix)
The Continuous Compliance engine, where connectors, rule sets, profiling jobs and masking jobs are defined. Section 28.1
Masking job (Delphix)
A saved set of options to apply a rule set's inventory, with a method, threads, memory and scripts. Section 26.1
Masking user (Delphix)
A dedicated database account for the connector, with only the permissions masking needs. Section 23.1
Match strength (Delphix)
A weight on one classifier match, such as 0.7 for a dashed SSN; several weak clues combine. Section 4.7
Meta Data Source (Delphix)
The connector screen grouping: Database, File or Mainframe. Section 23.1
Min Max (Delphix)
Pulls extreme values toward the middle, since the top salary may reveal a person. Section 26.4
Multi-Tenant (Delphix)
A job option letting one rule set serve identical schemas through different connectors chosen at run time. Section 23.9
Non-conformant data (Delphix)
A value not fitting the expected format. By default it stays unmasked and only a warning is recorded, so check job warnings. Section 22.7
Out-of-the-box instance (Delphix)
An instance shipping with the engine; it cannot be edited or deleted. Section 26.1
Payment Card (Delphix)
Keeps the first digits and the card's Luhn validity, masking the rest. Section 26.4
Profile set (Delphix)
A bundle of classifiers; choosing one decides which kinds of sensitive data a job can detect. Section 25.1
Profiling (Delphix)
Scanning column names and optionally data to find sensitive columns. Also called sensitive data discovery. Section 25.1
Profiling job (Delphix)
A saved instruction to scan a rule set using a profile set. Section 25.1
Record type and qualifier (Delphix)
When one file mixes layouts, a record type names each layout and up to three qualifiers recognise it. Section 27.6
Role (Delphix)
A set of allowed actions on object kinds; each user has one role and a list of environments. Section 22.9
ROWID (Delphix)
An Oracle pseudocolumn holding each row's address; recommended as the logical key for speed. Section 24.1
Rule set (Delphix)
The list of tables or files of one connector that jobs may look at. Four types: Database, Semi-Structured, Flat Files, Copybook. Section 24.4
SDD (Selective Data Distribution) (Delphix)
Replicating a masked VDB to another engine in non-production without sending unmasked data. Section 23.1
Secure Lookup (Delphix)
Picks a replacement from a lookup file by hashing the input, so output is consistent. Collisions are possible. Section 22.7
SecureShuffle (Delphix)
Moves each value to a different row; the values stay real and the result is not syncable. Section 6.4
Segment Mapping (Delphix)
Masks short values by segments with no collisions, if the allowed set is big enough; suits SSNs and keys. Section 22.7
Snapshot and TimeFlow (Delphix)
A snapshot is a dataset's state at one moment; the TimeFlow is the timeline of those states. Section 23.9
Stream (Delphix)
One parallel lane of work; more streams let the engine process several tables at once. Section 26.1
String Algorithm Chain (Delphix)
Runs two to eight string algorithms one after another. Section 6.4
Text enclosure and escape (Delphix)
The enclosure (often a double quote) wraps a value that may contain the delimiter; the escape writes a literal enclosure. Section 27.1
Tokenization (Delphix)
The only reversible family, using AES-128 and Base64; output is longer than input. Reversing it is re-identification. Section 26.9
Update threads (Delphix)
Parallel threads writing to the target database; too many can deadlock and each table needs an index. Section 26.11
VDB (virtual database) (Delphix)
A full read-write copy of source data provisioned from a dSource or another VDB, created in minutes. Section 23.9
Virtual appliance (Delphix)
