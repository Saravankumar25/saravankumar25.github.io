Encryption masking

What it does. Applies an encryption algorithm to a string column (User Guide 10.5.10, p.161 to 162) From docs. Two families:

TypeOptionsNotes
Standard EncryptionAES (Advanced Encryption Standard, 128-bit), CRC (cyclic redundancy check, a checksum for finding transmission errors), MD5 (one-way hash, 128-bit value)You enter an encryption key of 16 characters or fewer
Format Preserving EncryptionPreserve Format and Metadata; Preserve Metadata; Change MetadataCan be decrypted later with the same pass phrase and the same rule configuration. Not usable if the data has UTF-8 four-byte characters

The three format preserving options in the guide's own words (p.161 to 162):

  • Preserve Format and Metadata: keeps format and length. Upper case becomes upper case, lower case lower case, digits digits, special characters special characters. Example: Abc123@xyz.com may become Mpz849#dje!kuw; with "@" and "." set as Do Not Encrypt Characters, Mpz849@dje.kuw.
  • Preserve Metadata: keeps only length. Alexender may become jl6#HB91v.
  • Change Metadata: length and format change. London may become Xuep@8f5 or 6ky#ke33h*we. Before using it you must raise the column precision in the database (and in TDM) using: Required Precision = (1.33 x Original Precision) + 24, rounded up. After changing the database column, reimport metadata or edit the precision in Test Data Manager.
ParameterMeaning (p.162)
Encryption TypeStandard Encryption or Format Preserving Encryption
Encryption TechniqueThe technique to encrypt or decrypt the data
Encryption KeyInput key for standard encryption, 16 characters or fewer
Publish RuleMakes a format preserving rule read-only; only domain administrators can make it editable again or delete it
Do Not Encrypt CharactersCharacters left as they are. A leading or trailing space is respected but not displayed in the field

Use it when you must be able to get the original back (decryption is described only for format preserving encryption) or the application checks the shape of a value. Reversibility is also a risk: anyone with the key or pass phrase and the rule can recover production values The guide does not say where the pass phrase is entered. Same key and configuration give the same output for the same input.

Expression masking

What it does. Applies a PowerCenter-style expression to a column to create or change data. You build the expression in the Expression Builder by clicking columns, functions, variables and operators. Any datatype (User Guide 10.5.10, p.162 to 163) From docs.

Guide example: to join first names with the text ABC, enter CONCAT(FirstName,'ABC'). On ShopSphere Asha becomes AshaABC, a poor mask on its own but it shows the idea; a better use builds a value from other pieces, such as 'CUST' || customer_id.

ParameterMeaning
Repeatable OutputKeeps the masked value for a given column value; you must enter a seed if you enable it
Alphanumeric SeedAny text. Use the same seed in several rules that must return the same masked values
ExpressionA PowerCenter expression working on values in a single row

Gotchas (p.163): use it for one column (use advanced masking for several); make the expression return the column datatype, or you get zero (numeric) or NULL (string); one expression's output cannot feed another; repeatable output needs a storage table in the plan or the operation fails; no repeatable expression masking for Hadoop.

Nullification masking

What it does. Replaces the value with NULL. Works on binary, date, numeric and string data. No parameters (p.168) From docs.

Use it for columns the test environment does not need: the strongest privacy result. The target column must allow NULL, and the application may expect an SSN to exist.

SSN masking

What it does. Applies a built-in mask for Social Security numbers on string columns (User Guide 10.5.10, p.175) From docs. It generates valid-looking numbers and tries to avoid numbers the US Social Security Administration has actually issued, using the High Group List. The service reads that file from the PowerCenter installation's infa_shared/SrcFiles directory; you can download the latest version from the Social Security Administration. Any nine-digit input is accepted, with any delimiters.

Parameters. Repeatable Output with a seed value; an SSN randomization option, based on the method the Social Security Administration developed to remove the geographic meaning of the first three digits. No other parameter names are documented.

SIN masking

SIN is the Canadian Social Insurance Number (general background). The technique handles a nine-digit SIN with any delimiters on string columns (p.175) From docs: no delimiters in gives none out, otherwise xxx-xxx-xxx. Start Digit forces the first digit; Repeatable Output takes a seed. ShopSphere has no SIN column.

Phone masking

What it does. Changes phone numbers while keeping the original format; string columns only (p.169) From docs. The guide's example: (408)382 0658 becomes (408)256 3106. Input may contain digits, spaces, hyphens and parentheses; alphabetic and special characters are not masked. Example: 9876543210 might become 9876012345. No parameters are listed, and which digits are preserved is not documented; in the guide's example the first three stayed, but do not assume that holds for every format.

Credit card masking

What it does. Applies a built-in format to credit card numbers on string columns, producing a logically valid number with a valid checksum (User Guide 10.5.10, p.158 to 159) From docs. The source must be 13 to 19 digits with a valid checksum under card industry rules. It may contain numbers, spaces and hyphens. Invalid characters or length: the service logs an error in the session log and applies a default credit card mask. The six-digit Bank Identification Number (BIN) at the front is not masked. The guide's example: 4539 1596 8210 2773 may become 4539 1516 0556 7067.

Email masking

IP address masking

Splits an IP address into four numbers and masks the network number within its range; string columns (p.164) From docs. Class A stays Class A and 10.x.x.x stays 10.x.x.x: 11.12.23.34 may become 75.32.42.52, 10.23.24.32 may become 10.61.74.84. No parameters are listed.

URL masking

Masks URLs on string columns by finding :// and masking what follows (p.177) From docs; the protocol is not masked. http://www.yahoo.com may return http://MgL.aHjCa.VsD/, ASCII only and possibly invalid. No parameters are listed.
