Encryption masking

What it does. Applies an encryption algorithm to a string column (User Guide 10.5.10, p.161 to 162) From docs. Two families:

TypeOptionsNotes
Standard EncryptionAES (Advanced Encryption Standard, 128-bit), CRC (cyclic redundancy check, a checksum for finding transmission errors), MD5 (one-way hash, 128-bit value)You enter an encryption key of 16 characters or fewer
Format Preserving EncryptionPreserve Format and Metadata; Preserve Metadata; Change MetadataCan be decrypted later with the same pass phrase and the same rule configuration. Not usable if the data has UTF-8 four-byte characters

The three format preserving options in the guide's own words (p.161 to 162):

  • Preserve Format and Metadata: keeps format and length. Upper case becomes upper case, lower case lower case, digits digits, special characters special characters. Example: Abc123@xyz.com may become Mpz849#dje!kuw; with "@" and "." set as Do Not Encrypt Characters, Mpz849@dje.kuw.
  • Preserve Metadata: keeps only length. Alexender may become jl6#HB91v.
  • Change Metadata: length and format change. London may become Xuep@8f5 or 6ky#ke33h*we. Before using it you must raise the column precision in the database (and in TDM) using: Required Precision = (1.33 x Original Precision) + 24, rounded up. After changing the database column, reimport metadata or edit the precision in Test Data Manager.

Use it when you must be able to get the original back (decryption is only described for format preserving encryption), or when the application validates the shape of a value. Gotchas. Reversibility is a feature and a risk: anyone with the key or pass phrase and the rule can recover production values, so a masked copy using decryptable encryption is not as safe as one using substitution (my note, General concept; the guide only states that decryption is possible). The guide does not say where the pass phrase is entered for format preserving encryption in the excerpt I had, so check your version. The guide calls MD5 a "one-way" hash; it describes decryption only for format preserving encryption. Repeatability. Encryption with the same key and configuration gives the same output for the same input; the guide stresses the same pass phrase and configuration to decrypt.

Expression masking

What it does. Applies a PowerCenter-style expression to a column to create or change data. You build the expression in the Expression Builder by clicking columns, functions, variables and operators. Any datatype (User Guide 10.5.10, p.162 to 163) From docs.

Guide example: to mask first names by joining them with the text ABC, select the FirstName column and enter CONCAT(FirstName,'ABC'). On ShopSphere that turns Asha into AshaABC. That is a poor mask on its own (the real name is still visible) but it shows how expressions work. Better uses: building a value from other pieces, for example 'CUST' || customer_id.

ParameterMeaning
Repeatable OutputKeeps the masked value for a given column value; you must enter a seed if you enable it
Alphanumeric SeedAny text. Use the same seed in several rules that must return the same masked values
ExpressionA PowerCenter expression working on values in a single row

Gotchas (p.163): use expression masking for one column; for several columns use advanced masking. Make the expression return the column's datatype: the service returns zero for a numeric mismatch and NULL for a string mismatch. You cannot use one expression's output as another's input. With repeatable output you must name a storage table in the plan or the operation fails. No repeatable expression masking for Hadoop sources. Expression syntax is in the Informatica Transformation Language Reference, which the guide points to and I did not read.

Nullification masking

What it does. Replaces the value with NULL. Works on binary, date, numeric and string data. No parameters (p.168) From docs.

Nullification on ssn and tax_id (illustrative)
customer_idssn beforessn after

1002234-56-7890NULL

Use it for columns the test environment does not need at all: the strongest privacy result, since nothing is left. Gotchas. The target column must allow NULL, or the load fails. The application may validate that an SSN is present. Not repeatable in any meaningful way since every row gets the same NULL. A related plan setting, "Target Empty Value", exists in the New Project dialog for non-null columns (p.56), but that is a project setting, not part of this technique.

SSN masking

What it does. Applies a built-in mask for Social Security numbers on string columns (User Guide 10.5.10, p.175) From docs. It generates valid-looking numbers and tries to avoid numbers the US Social Security Administration has actually issued, using the High Group List. The service reads that file from the PowerCenter installation's infa_shared/SrcFiles directory; you can download the latest version from the Social Security Administration. Any nine-digit input is accepted, with any delimiters.

Parameters. Repeatable Output with a seed value; an SSN randomization option, based on the method the Social Security Administration developed to remove the geographic meaning of the first three digits. The excerpt does not give more parameter names.

SSN masking (illustrative output)
customer_idssn beforessn after

Gotchas. With repeatable masking the output is deterministic, but TDM "cannot return all unique" SSNs, because it cannot return valid numbers that have already been issued: do not use SSN masking on a column that has a unique constraint without testing for duplicates. Also, an unrelated check: the ShopSphere source ssn is a string with hyphens; the masked output keeps that style, which is what the application's validation probably wants. Repeatability. Select Repeatable Output, select Seed, enter a value.

SIN masking

SIN means Social Insurance Number, the Canadian equivalent. The technique handles a nine-digit SIN with any delimiters, on string columns (p.175) From docs. With no delimiters in the input the output has none; otherwise the output format is xxx-xxx-xxx. You can enable Start Digit and give a digit so all masked SINs start with it. Repeatable Output with a seed value is supported. ShopSphere does not hold SINs, so there is no table for it; use the same thinking as for SSN.

Phone masking

What it does. Changes phone numbers while keeping the original format; string columns only (p.169) From docs. The guide's example: (408)382 0658 becomes (408)256 3106. Input may contain digits, spaces, hyphens and parentheses; alphabetic and special characters are not masked. The excerpt lists no parameters, and does not say which digits are preserved; in the example the first three stayed, but I would not assume that rule holds for every format.

Gotchas. If your phone column contains words like "ext 12", only digits are masked. Repeatability is not mentioned for phone in the excerpt. If you need the same phone masked the same way in two tables, use key masking with a numeric mask format and the same seed instead (a design alternative, General concept).

Credit card masking

What it does. Applies a built-in format to credit card numbers on string columns, producing a logically valid number with a valid checksum (User Guide 10.5.10, p.158 to 159) From docs. The source must be 13 to 19 digits with a valid checksum under card industry rules. It may contain numbers, spaces and hyphens. Invalid characters or length: the service logs an error in the session log and applies a default credit card mask. The six-digit Bank Identification Number (BIN) at the front is not masked. The guide's example: 4539 1596 8210 2773 may become 4539 1516 0556 7067.

Email masking

What it does. Generates realistic email addresses on string columns. It can build the user name from the masked first and last names, and use a constant or a dictionary-chosen domain (p.159 to 161) From docs. Output is always ASCII. It can be repeatable between workflows or within one workflow.

IP address masking

Splits an IP address into four period-separated numbers and masks the network number within its network range; string columns only (p.164) From docs. It does not change the class or private network: a Class A address stays Class A and a 10.x.x.x address stays 10.x.x.x. Guide examples: 11.12.23.34 may become 75.32.42.52 and 10.23.24.32 may become 10.61.74.84. The excerpt lists no parameters. ShopSphere has no IP column; an example would be a web log table with client IPs.

URL masking

Masks URLs on string columns by finding :// and masking what follows; the source must contain ://; numbers and letters are allowed (p.177) From docs. The protocol is not masked. The guide's example: http://www.yahoo.com may return http://MgL.aHjCa.VsD/. Output is always ASCII and may be a URL that is not valid, so do not use it where the application opens the link. No parameters are listed in the excerpt.
