14.3 Creating masking rules

A rule is created in the Policies view, then added to a project, then assigned to columns. The guide recognises three kinds (User Guide 10.5.10, p.136 to 138) From docs:

KindWhat it isColumnsUse it when
StandardA built-in technique with parameters. One masking technique per rule.One input column, one output columnMost cases: mask a name, an SSN, a date
AdvancedA combination of techniques; masks multiple source columns, or one column based on more than one input.Input, variable and output columnsA full name built from masked first and last name; conditional masking; dependent columns
MappletLogic imported from a mapplet exported from PowerCenter or the Model repository.Multiple input and output columnsYou need a PowerCenter masking technique TDM does not offer natively

Creating a standard rule

  1. Click Policies, then Actions > New > Masking Rule.

    The Rule Wizard opens (User Guide 10.5.10, p.139).

  2. Enter a name and optional description. Pick the datatype of the column the rule will be applied to.

    Techniques depend on datatype: you cannot blur a string by a percentage. A rule can be created for string, numeric and date types (p.72).

  3. Select the Standard masking rule type. Tick Override Allowed if users may change parameters when they assign the rule. Click Next.

    Override is described below. The next screen changes depending on the masking technique you select (p.139).

  4. Enter the masking parameters.

    These decide exactly how values are masked: dictionary, seed, range, mask format and so on. Section 14.6 lists them per technique.

  5. Enter the exception handling options.

    Decide what to do with nulls, empty spaces and errors (14.5). Click Finish (p.139 to 140).

    The rule appears in the Policies view and can be edited, copied (Actions > Duplicate) or deleted there (p.139, p.146).

Previewing a rule: the Rule Simulator

The guide describes a built-in preview so you do not have to run a full workflow to see what a rule does (User Guide 10.5.10, p.137, p.140) From docs. It works for standard rules only (the text says "simulate the output of a standard rule").

  1. Policies view, click a masking rule name to open its Rule Properties, then click Rule Simulator.

    This opens the simulator tab.

  2. Choose a source in Source Details: Default, My Test Data or Connection, then click Edit.

    Default uses sample data supplied by TDM. My Test Data lets you type rows (up to 100). Connection reads real rows (the Configure Source Details page opens).

  3. If Connection: open the Connection tab, pick connection and owner, Browse to the table, choose the column.

    By default up to 10 random columns are listed; type the column name if yours is missing. Enter the number of rows: default 20, maximum 100. Click OK.

  4. Click Go.

    The Rule Simulator tab lists original values beside masked values.

  5. Adjust the rule and run the simulation again on the same data.

    The latest simulation configuration is stored in the browser cache, and clearing the cache deletes it (p.137).

Override

With Override Allowed ticked, whoever assigns the rule may change its parameters for one column (p.136, p.146): select the column, Actions > Override, edit, Save. The Override column then reads Yes-Overridden. Different overridden seeds on columns that must match will break the match.

Creating a mapplet rule

The wizard path (p.140 to 141): Policies, Actions > New > Masking Rule, name, datatype, Mapplet masking type, browse to the exported XML (for Hadoop, select Hadoop and browse to a Developer tool mapplet), Next, mark at least one input and one output column as mandatory, Finish. Details and limits are in 14.9, which also walks through building a small mapplet in PowerCenter first.

Creating an advanced rule

  1. Policies, Actions > New > Masking Rule. Enter a name and description, choose Advanced, click Next.

    Advanced rules combine techniques (User Guide 10.5.10, p.141).

  2. In Input Columns click Add New. Give the name, datatype, precision and scale. Choose whether assigning it is mandatory in every project.

    You cannot enter masking properties on input columns, because input columns just receive the source value.

  3. In Variable Columns click Add New. For each, enter an expression, a masking rule or a dependent column.

    Variable columns are scratch fields for intermediate results. If you apply a masking rule, say which input column feeds it.

  4. In Output Columns click Add New. Enter an expression, a masking rule or a dependent column.

    The output column receives the final value written to the target.

  5. Click OK and finish.

    The column names in the rule do not have to match source column names; you map them at assignment time (p.156 to 157).

The full parameter tables for advanced rules are in 14.8.

14.4 Assigning rules to columns

Add rules to the project first

Rules live in the Policies area; a project only sees them after you add them. Projects, open the project, Overview > Policies, Actions > Add Additional Rules, tick your rules, OK; they appear under Additional Rules (User Guide 10.5.10, p.141 to 142) From docs.

The Define | Data Masking view

Assignment happens in the project's Define | Data Masking view (p.138 to 139). Each row is one column of the source.

Column in the viewMeaning (p.138 to 139)
Name / Owner / ColumnsTable name, schema name, column to mask
Data TypeDatatype of the column

SensitiveYes or No: whether the column is marked sensitive
Similar Value ColumnsNumber of other columns in a cascade with this one

Assigning a standard rule, step by step

  1. Open the project, click Define | Data Masking, select a column.

    Choose the column that needs masking, for example CUSTOMERS.first_name.

  2. If Domain is blank, click the Policy column and pick a policy that contains the rule you want.

    The list of rules comes from the data domain's preferred rules, then the policy's rules (p.142, p.145).

  3. Click inside the Masking Rule column and pick a rule.

    Domain preferred rules are at the top; the rest of the policy's rules are below. For a substitution rule you can set the rule assignment parameters (lookup condition, unique substitution column, see 14.6). For a mapplet or advanced rule you map columns (below).

  4. Click Save for each column.

    If you move to another row without saving, TDM discards the assignment (p.145). This is the most common beginner loss.

  5. If you changed an assignment that other objects use, the Impacted Objects dialog lists plans, columns and domains.

    Click Export for a CSV, Continue to save. Regenerate and rerun the affected plans (p.142).

No rules appear in the list?

No rules listed? Check that a rule exists for the column datatype, that the project has a policy with masking rules, and that the domain's preferred rule is in a policy assigned to the project (p.145). The Integration Service does not mask integers longer than 28 characters (p.145, p.152).

Assigning a mapplet or advanced rule (port mapping)

These rules have named input and output ports, so you map source columns to them (User Guide 10.5.10, p.142 to 143) From docs. Pick the rule in the Masking Rule column; a Custom Rule Assignment or Advanced Rule Assignment dialog opens. Select a source column and a same-datatype rule input port, click Link (or Show Simple), then Next, link rule output ports to source columns, Save. For an expression cascade in an advanced rule, Add Associated Table lets you combine two tables with a join condition. Sybase to Hadoop limits a custom rule to 20 columns (p.143).

Many columns, many rules

  • One rule on many columns: search for similar columns, for example all ID columns, tick them and click Single Rule Assignment. Pick a policy and a masking rule, click OK (p.147 to 148). The guide's figure on p.148 shows this dialog.
  • Clearing: select the column and click Clear Assignment, confirm, and Continue if the Impacted Objects dialog appears (p.148).

Cascades: keeping values consistent between tables

The ShopSphere customer_id is a primary key in CUSTOMERS and a foreign key in ORDERS. If you mask the key but the foreign key keeps its old value, the join breaks. TDM handles this with cascades (User Guide 10.5.10, p.90 to 91) From docs:

  • Auto cascade: masks a primary key in a parent table and the related foreign keys in child tables with the same value. Applied by default to tables with key constraints; can be switched off or on. Needs key constraints between parent and child. Not available for XSD, MongoDB and Cassandra sources.
  • Value cascade: for similar columns not linked by key constraints (the guide's example: employee_num in one table and EmpID in another). Select the columns in Discover | Columns, Actions > Set as similar value columns, and choose a driving column. A rule assigned to the driving column is assigned to all the group. The columns must have the same type. In the masking view the driving column shows the number of other columns in the cascade.
  • Not for computed columns: you cannot apply masking or generation rules to computed columns or build cascades on them (p.90).

Changing or deleting rules after assignment

Editing or deleting a rule shows an Impacted Objects dialog, but changes do not flow into plans: regenerate and rerun them. Deleting a rule does not remove it from the columns, domains and plans using it. If you change a custom rule's field names or types, import the mapplet again (p.144 to 146) From docs. For XSD sources you apply rules to XML elements and attributes in Discover > Files (p.144); shuffle is not allowed for XSD (p.135).

14.5 Parameters that most techniques share

Before the techniques, three ideas appear again and again (User Guide 10.5.10, p.153 to 155) From docs.

Repeatable output and the seed

Repeatable output returns deterministic values: the same input gives the same masked value, every time you generate and run the workflow. Use it when the same value occurs in several tables and the target tables must show the same masked value. The guide's example: customer John Smith has account numbers 1234 and 5678 in many tables; masking turns John Smith into Frank Martinez everywhere, 1234 into 6549, 5678 into 3214, on every run.

The seed is the generator's starting point: 1 to 999, default 1 (p.154; the key masking string table says 1,000, p.168, so I use 999). Give the same seed to columns that must match, such as Cust_ID in four tables. You can put the seed in a parameter file variable. A TDM administrator can set a central seed that overrides every other seed (p.155).

Substitution and expression masking keep a storage table of source and masked value pairs; you name the storage connection in the plan (p.286: IDM_SUBSTITUTION_STORAGE, IDM_EXPRESSION_STORAGE), and expression masking fails without it (p.163). Key masking is deterministic from source, rule and seed (p.164). Repeatable means "same in, same out", not "reversible".

Exception handling

Every rule has an Exception Handling section that decides what happens with nulls, blanks and errors (p.155):

OptionWhat it does
Preprocessing ExpressionOptional expression applied to the data before masking
Post processing ExpressionOptional expression applied to the masked data before it is written
Null and Empty SpacesConstant (mask with a value you give); Log error and continue; Treat as value (mask the space or null as a valid value); Ignore (leave it unmasked). For dependent masking columns there is no separate rule: they follow the column they depend on.
Error HandlingConstant; Log exception and continue; Ignore and continue; Error (log and stop)
Trim Leading or Trailing SpacesWhen on, " Jones", "Jones" and "Jones " are the same value
