Running the masking operation: the guide's steps

The guide's list for performing a masking operation (User Guide 10.5.10, p.148 to 149) From docs, with reasons:

  1. Create a data masking rule.

    The rule is the recipe (14.3). Preview it in the Rule Simulator.

  2. Create a project and import metadata.

    The project knows the tables and columns. Use separate projects for XSD and relational sources.

  3. Optional: create parameters or import global parameters.

    For example a seed variable in a parameter file, so you can change the seed without editing the rule (p.155).

  4. Add the rule to the project.

    Projects only see rules you add (14.4).

  5. Assign the rule to a target column (or to an XML element).

    This is where you say "mask ssn with SSN_Rule". Save each row.

  6. Create a plan, add the rule, and configure source and target connections.

    A plan holds at least one rule or policy. It states whether data is masked in place in the source database or in stream into a target (p.150). Add a storage connection if any rule is repeatable substitution or expression masking (p.286).

  7. Generate and run the workflow.

    PowerCenter creates mappings, sessions and a workflow and runs them (p.150). Use Actions > Generate and Execute, then pick parameter values (p.310 to 311).

  8. Monitor the workflow.

    Check Workflow Executions for Success, then open the logs if not (p.311 to 312).

    Target columns hold masked values; source untouched (when masking in stream into a target).

Plans and workflow settings are in the Informatica plans, workflows and warehouse chapter. If you also subset, masking runs on the subset result (p.275), as in the Informatica data subset chapter.

14.12 Common mistakes and gotchas

Watch out for these
  • Forgetting to click Save after each assignment; TDM discards unsaved assignments (User Guide 10.5.10, p.145).
  • Not rerunning plans. Edits to rules, assignments or domains do not change existing plans until you regenerate and run them (p.144 to 148).
  • Different seeds on columns that must match. The same seed gives the same output across columns (p.154, p.167). Different seeds give different values, and joins break.
  • Repeatable substitution or expression masking with no storage table. Expression masking fails; substitution cannot remember pairs (p.163, p.176, p.286).
  • Unique substitution with a short dictionary. The operation fails (p.176).
  • Short mask formats. Trailing characters stay unmasked (p.164).
  • Masking the primary key but not the foreign key. Use auto cascade, value cascade or the same seed (p.90 to 91, p.167).
  • Shuffle on XSD or Spark, expression repeatable on Hadoop, flat-file dictionaries on Hadoop. Documented as unsupported (p.62, p.135, p.163, p.176).
  • Expecting reversibility from the wrong technique. Only format preserving encryption is described as decryptable (p.161).

14.13 Recap

Key points
  • A rule is a technique plus parameters. Rules attach to columns directly or through data domains, which a policy groups for reuse. Always preview a standard rule in the Rule Simulator.
  • Three rule kinds: standard (one input, one output), advanced (input, variable, output columns with expressions, conditions and dependent masking) and mapplet (imported PowerCenter logic made of passive transformations including Data Masking transformations).
  • Repeatable output and a seed make masking deterministic. Substitution and expression masking also need a storage table.
  • Substitution gives realistic values from a dictionary; shuffle moves real values between rows; key masking keeps character types deterministically; random masking uses ranges and blurring; encryption can be reversible; nullification empties the column; SSN, SIN, phone, credit card, email, IP and URL are built-in formats.
  • Choose by what the application needs: realism, format validity, joinability across tables, reversibility, or nothing at all.
  • The guide covers importing and assigning mapplet rules but does not teach building the mapplet in PowerCenter.
  • Masking happens after subsetting when both are in one plan.
