12.3 The Discover view

Inside a project, the Discover tab is where profiling happens (User Guide 10.5.10, pp.88-89). Its sub-views: Tables (tables, relationships, columns; define keys; delete a table; disable a physical primary key you do not need; edit a column's precision), Profile (define profiles), Columns (maintain domain assignments, mark columns Restricted or Sensitive, assign domains in bulk, define value cascades) and Files (XSD files).

Visual reference Informatica TDM 10.5.10 User Guide, p.88, Figure "Discover view in a Project". What to look for: the Tables, Profile, Columns and Files sub-tabs, a table list, and a Relationship Overview pane that draws the selected table with its related tables.

Column properties

Discover > Columns shows Table Name, Column, Owner (the schema), Data Type, Domain, and three flags (p.89):

  • Restricted: the Integration Service does not write the value to a target.
  • Computed: the value is calculated from other columns, for example Net_Pay = Basic_Salary + Allowances - Tax_Deduction. You cannot assign masking or generation rules or cascades to it, and TDM does not copy data into it because the database recomputes it (p.90).
  • Sensitive: a label for people only; it does not affect processing. Assigning a data domain marks the column sensitive automatically.

A Similar Value Columns count shows how many columns share a value cascade with this one.

Value cascades and auto cascades

Both make sure the same original value becomes the same masked value in several places. That is the difference between a customer whose id looks right everywhere and one whose id no longer matches across tables.

Auto cascade (keys exist)

Masks a parent table's primary key and the related foreign keys in child tables with the same value. Applied by default to tables with key constraints; you can enable or disable it. It needs key constraints between parent and child. Not available for XSD, MongoDB and Cassandra sources (p.91).

ShopSphere: mask CUSTOMERS.customer_id and ORDERS.customer_id receives the same masked value.

Value cascade (no keys)

Masks similar columns in different tables the same way when they are not linked by key constraints. You group similar columns and mark one as the driving column; a rule assigned to it goes to all the others. The columns must have the same type (p.90).

ShopSphere: an email column in CUSTOMERS and a contact_email column in some marketing table.

The guide's example: employee_num in one table and EmpID in another are similar value columns, with employee_num driving. Assign a rule to it and EmpID receives the same rule (p.90). The driving column shows a number in Similar Value Columns; the others show none.

  1. Create: in Discover > Columns select the columns, click Actions > Set as similar value columns, and click the driving-column checkbox to change No to Yes for one column (p.90).
  2. Change: select the driving column (it has a number), open the Similar Value Columns view in the Details panel, click Edit Similar Value Columns. Set Driving Column to Yes on another column (the previous one switches to No), use Add to add columns or Delete to remove them (p.91).
  3. Delete the group: select the driving column, open Similar Value Columns, select any column in the group, click Delete, confirm (p.91).

12.4 The discovery task flow

Before profiles can run, the administrator must configure a source database connection for discovery plus connections to the Data Integration Service and Model Repository Service (User Guide 10.5.10, p.92). The steps (p.92):

  1. Create a profile and choose its type (primary key, entity or data domain; primary key can combine with the others).
  2. For a data domain profile, choose domains or policies, then choose the sampling size.

    More rows is more reliable and slower.

  3. Run the profile and watch the job in Monitor.
  4. Close and reopen the profile, review the results, then approve the ones to use.

    The guide says results show only after you reopen it (p.103). Approval applies them.
