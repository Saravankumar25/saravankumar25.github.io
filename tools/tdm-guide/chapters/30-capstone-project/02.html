30.4 Activity 1: profile and mask FirstName and LastName

Brief

Inputs. CUSTOMERS with first_name and last_name; the "before" snapshot; two edge rows added for this activity: (1005, 'Ann-Marie', 'von Wilke') and (1006, 'S.', 'K.'), plus the duplicate-name row 1004 (Asha Iyer) from the labs. Tool. Delphix primary; Informatica as a cross-check. Output. Masked names, an inventory showing the two assignments, verification output, and a note on every decision.

Steps

  1. Connect and profile.

    Follow Labs 4 and 5 in the Delphix labs; concepts in the Delphix profiling chapter. For Informatica, the equivalent is a data domain profile (see the Informatica profiling chapter).

    first_name is assigned FIRST_NAME and last_name LAST_NAME, as the official profiling screenshots show; record each assignment and who confirmed it.

  2. Choose the algorithms and write down why.

    Delphix: dlpx-core:FirstName and dlpx-core:LastName. From docs Both are instances of the Name framework; they are deterministic, require string input, return null, empty and whitespace-only values unmasked, and are not unique, so a masked value may equal the input (FirstName, LastName). A single character is treated as an abbreviation and masked to a single character; hyphenated words count as one word. The default FirstName instance returns at most two names; the LastName instance is configured with a particles file and masks only the first word after removing particles. Informatica alternative: substitution masking from a name dictionary, with Repeatable Output for the same replacement each run (User Guide 10.5.10, pp.154, 176 to 177).

  3. Mask only these columns.

    Use a rule set whose inventory has just these two assignments (duplicate, clear, assign), as in Lab 7, and run an in-place job on a restored or snapshotted copy.

  4. Verify and collect evidence using the queries below and the job's execution summary.

30.5 Activity 2: profile and subset

Brief

Goal. Produce a smaller copy of ShopSphere that is still referentially intact: a chosen set of customers with all their orders, all the items of those orders, and the products those items use. Inputs. A source with enough rows to make a subset visible: at least 30 customers across several postal prefixes, with orders and items. If your source is only the three lab rows, generate more: GenRocket produces fake rows without touching production, using generators such as NameGen, PhoneNumberGen and SSNGen (five key components; SSNGen sequential or random: SSNGen). Criterion (my choice). Customers whose zip_code starts with 560.

Steps with Informatica TDM (primary)

  1. Create a project and import the metadata.

    The process (User Guide 10.5.10, pp.30 to 32) starts with a project and imported source metadata. See the Informatica tour.

  2. Profile keys and relationships.

    Run primary key and entity profiles where keys are not declared, and apply the results (p.31; the Informatica profiling chapter). A subset follows relationships, so missing or undeclared ones (for example ORDER_ITEMS to PRODUCTS through product_code) give a broken subset.

  3. Create an entity with CUSTOMERS as the driving table.

    The guide says an entity is a driving table plus related tables, found by physical and logical constraints; you add filter criteria on a column, which can be a value or a parameter changed at run time (pp.113 to 114). Put the criterion on zip_code and check the Entity Map: confirm ORDERS, ORDER_ITEMS and PRODUCTS are present and the relationships are enabled. See the Informatica subset chapter.

  4. Create a subset plan, generate the workflow and run it.

    Add the entity to a plan with a target connection (plans and workflows). The guide notes a masking and a subset operation can share one plan (p.32), which is what a real project would do so the subset is never exposed unmasked.

  5. Run the Row Count Report on the plan: it lists the tables and rows each plan affects (p.324). Keep it as evidence.

Alternatives, to name but not use as primary. Delphix rule sets accept a per-table filter (customers.zip_code LIKE '560%', with the table prefix on the column, as the docs show) or custom SQL that must include the key columns; the pages I read do not describe following related tables automatically, so related-table filters would be yours to write (Managing rule sets). GenRocket's G-Subset subsets by a where clause, percentage or row count, supports no composite keys, and migrates only between databases of the same type (G-Subset overview).

-- 5 items without a product
SELECT COUNT(*) FROM order_items i LEFT JOIN products p ON p.product_code = i.product_code WHERE p.product_code IS NULL;

Evidence: profile results, entity map screenshot, Row Count Report, the five query outputs, a table of source against target row counts with the ratio, and the criterion you chose and why.

A subset is real data

A subset copies real rows. Until it is masked (Activities 1 and 3), treat the subset target as sensitive. Say so in your report, and say how you would combine the two in one plan.
