This worked project applies the earlier techniques to ShopSphere in three parts: profile and mask FirstName and LastName; profile and subset; profile and mask SSN, alphanumeric values, TaxID and ZipCode. Each part has a goal, a tool, configuration steps, validation criteria and test queries. The main design question is how to mask SSN, TaxID and ZipCode while keeping format and integrity; documented facts are kept apart from design choices.

30.1 Words to know first

Acceptance criterion
A measurable statement that decides whether a piece of work is done, such as "0 orphan orders".
Deterministic masking
The same input always gives the same masked output (for the same algorithm and key). It lets one SSN mask identically in a database and a file.
Format-preserving
The masked value has the same shape as the original: same length, same dashes, digits stay digits.
Referential integrity
Every foreign key still points at an existing row, so joins still work (data basics).

30.2 The project at a glance

The running example is ShopSphere again: CUSTOMERS, ORDERS, ORDER_ITEMS and PRODUCTS, plus two additions, membership_code (an alphanumeric value such as SS-A7K29X) and a customer extract file. The sample rows use six-digit postal codes (560001) and a US-style SSN (123-45-6789), and TaxID is a nine-digit value such as 98-7654321.

30.3 Preparing the source

Set up the lab database and files, with enough rows to make a subset visible (generate more if needed). Take a "before" snapshot, which the test queries compare against as customers_before, record baseline counts, and confirm the orphan queries return 0 on the source. All masking runs on a restorable copy; production is never touched.
