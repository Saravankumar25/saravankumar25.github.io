The programme ends with a project, evaluated by the business-unit subject-matter expert (BU SME) in the final project evaluation and the final technical evaluation on Days 58 to 60. The syllabus lists three activities: data profiling and masking of FirstName and LastName; data profiling and a data subset; and data profiling and masking of SSN, alphanumeric values, TaxID and ZipCode. It also says progress is checked daily, so this chapter gives you a day-by-day plan, a brief for each activity, acceptance criteria you can test with queries, and the evidence to collect.

Nothing new is taught here. Each step links to the chapter or lab that teaches it. What is new is the set of design decisions, mainly how to mask SSN, TaxID and ZipCode while keeping format and integrity. Every such decision is labelled as taken from the documentation or as my own design.

30.1 Words to know first

Activity
One of the three syllabus project parts. Each ends with verified output and evidence.
Acceptance criterion
A measurable statement that decides whether an activity is done, such as "0 orphan orders".
Deterministic masking
The same input always gives the same masked output (for the same algorithm and key). It lets one SSN mask identically in a database and a file.
Format-preserving
The masked value has the same shape as the original: same length, same dashes, digits stay digits.
Referential integrity
Every foreign key still points at an existing row, so joins still work (data basics).
Evidence pack
The collection of queries, screenshots and reports that proves each acceptance criterion, as in the Delphix labs.
