30.11 Common mistakes and gotchas

Common mistakes
  • Masking a key to "be safe". It breaks joins. Leave keys alone unless the same deterministic algorithm is applied on both sides.
  • Different algorithms for the same value. An SSN masked differently in the database and the file ruins consistency; reuse one instance.
  • Numeric columns and leading zeros. Digit masking on a numeric zip or tax id can collide; keep such values as text or use the numeric algorithm.
  • Trusting profiling for six-digit postal codes. The documented ZIP data patterns target US formats; the column name does the work.
  • A subset left unmasked. It is real data; mask it in the same plan.
  • Presenting design choices as product facts. CM Digits is a suitable choice for SSN, not the product's SSN algorithm.

30.12 Recap

Recap
  • The project has three parts: names, subset, and SSN, alphanumeric values, TaxID and ZipCode.
  • Use Delphix for the masking parts and Informatica for the subset, with the other tool as a cross-check and GenRocket for fake source rows.
  • Every part has acceptance criteria that a query or report can prove.
  • Format-preserving, deterministic algorithms (CM Digits, CM Alpha-Numeric, a Character Mapping instance with a preserve range, or Informatica key masking with a mask format and seed) keep shape and consistency. Segment Mapping and Informatica SSN masking are documented alternatives with their own limits.
  • Integrity means both intact foreign keys and the same value masked the same way in every system.
  • A subset is real data until it is masked.
  • Keep documented facts apart from design choices, and explain every warning.
