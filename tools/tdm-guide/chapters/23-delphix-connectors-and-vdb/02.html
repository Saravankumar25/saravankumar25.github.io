23.3 Connectors: what they are

A connector is a saved answer to the question "how does the engine log in to this data?". Without it, the engine has nowhere to read tables from. Connectors are grouped within an environment: open the environment and click its Connectors tab. From docs

There are three families, shown as groups on the Connectors screen (the page calls the grouping field "Meta Data Source").

Meta Data SourceWhat it points atExamples of Type (from the docs and screenshots)
DatabaseA relational database reached over JDBC.Oracle, MS SQL, Sybase, Mysql, Postgres, Db2 and Extended (see below).
FileFiles in a directory or storage location.Delimited, Fixed Width, XML, JSON, Parquet.
MainframeMainframe data sets, usually encoded in EBCDIC (the mainframe character encoding).Dataset.

The columns are: Connector ID (used by the API), Name, Type and Actions (Edit, Test Connection, Delete). You can filter and sort by ID, Name and (filter only) Type inside each group.

Encryption is not on by default

The connectors page states that connections are not encrypted by default, but you can enable TLS/SSL. The per-database pages (for example Oracle and SQL Server) explain how, typically by importing the database's certificate into the engine's truststore through the setup application, restarting the engine, and using a JDBC URL that asks for TLS. For Oracle the page adds that SSL with the BASIC Oracle connector is not supported, so you must use an advanced (JDBC URL) connector for TLS. For SQL Server the page says the needed JDBC properties depend on your instance and your DBA must supply them.

23.4 Creating a connector: the wizard, field by field

Click + Connection (or "+ Connector") at the top right of the Connectors tab. A wizard opens with steps down the left side: Details, Credentials, Custom Properties (database connectors only; file connectors skip it) and Summary. Every step has Cancel, Back, Next, Test Connection and Save buttons at the bottom, so you can test at any step. From docs

23.4.1 Step 1: Details

  • Connector Name. A name of your choice. In the screenshots the label reads "Connection Name" or "Connector Name" depending on release. The same naming restrictions apply as for other objects. For ShopSphere: SHOPSPHERE_VDB_CONN.
  • Source Type. The kind of data source. Each entry in the dropdown is prefixed with its Meta Data Source, for example "Database - Sybase", "File - Delimited" or "Database - Extended".
  • Connection Mode (Oracle, MS SQL Server and Sybase only): Basic asks for host, port and so on; Advanced asks for the full JDBC connect string including any database parameters. In the screenshot of this step, the same choice is labelled "Select Connection Method" with the options "Hostname/IP (Basic)" and "JDBC URL (advanced)". The docs say Basic and Advanced are not available for all source types.

23.4.2 Step 2: Credentials for a database connector

The fields that appear depend on the source type, and the docs say to ask your DBA if you are unsure of a value. This is the full documented list of database fields.

FieldMeaning (from the docs)Watch out for
Schema NameThe schema containing the tables this connector will access.A schema is a named group of tables inside a database. The rule set can only list tables in this schema.
Database NameThe database you connect to.Case-sensitive. It must match exactly the name as the instance knows it. The 2026.5 release notes even fix a case where leading or trailing spaces here passed the connection test but made jobs fail.
Host Name/IPNetwork name or address of the database server.The engine itself must be able to resolve and reach it.
PortTCP port of the server.For MS SQL Server optional: defaults to 1433 and need not be specified if the server uses it.
SID(Oracle only) the Oracle System ID.
Instance Name(MS SQL Server only, optional) the instance name.If given, the connector ignores Port and contacts the SQL Server Browser Service on port 1434 to learn the instance's port. So the firewall must allow 1434 and the instance's port.
JDBC URL(Advanced mode for Oracle, MS SQL Server and Sybase) the custom URL, typically with host and port.Also used by Generic and Extended connectors.
Authentication type, Username, PasswordThe login the connector uses.The password is stored encrypted. Options below.

The authentication type dropdown is offered according to the source type. The authentication-types page describes three kinds. From docs

  • Username/Password. The simplest. The password is stored encrypted.
  • Kerberos. The engine authenticates to the Kerberos server first, then uses its Kerberos credentials instead of a password. The Login ID is then treated as the Kerberos user principal name, and extra fields (Principal Name, and for Sybase a Service Principal) appear. The appliance must be configured for Kerberos beforehand, and Kerberos is disabled in containerized masking.
  • Password Vault. The engine asks an external vault for the credentials using a Credential Path you enter. The vault must be configured first.

23.4.3 Step 3: Custom Properties

Optional. Use it to upload a connection properties file, normally a Java properties file (lines of key=value), that adds settings to the JDBC connection. The rules, all from the managing-connectors page: the file must have the extension .properties and follow Java properties syntax; it is read as ISO 8859-1 text; any property you list is passed to the driver even if the driver does not officially support it, and every property loaded is logged.

When the same property can be set in several places, the engine applies a fixed order. This matters when a connector "ignores" something you typed. From docs

PropertyWinner, then runner-up
Username, Password, SchemaThe form field always wins.
Everything else (database name, host, port, SID, instance name, other driver properties)1. The properties file, 2. the form fields, 3. the JDBC URL.

The page adds that the JDBC driver itself decides what happens with duplicates, and that a connector form shows either the Basic fields or the Advanced URL, never both, so those two cannot clash. It also notes a driver quirk: for Caché DB the schema cannot be set through the URL, so it has to come from the form field or a properties file. Customising the JDBC URL is limited to Advanced, Generic and Extended connectors, while a properties file works for every database connector.

Secrets in properties files are visible

Anything in a properties file, including a password, is shown in plain text to every user who has the View Connector privilege. The page recommends putting sensitive values in the form fields (obfuscated everywhere) or, second best, in the JDBC URL (plain text on screen but redacted in support bundles).

23.4.4 Step 4: Summary and Save

The last step lists everything you entered (without the password) so you can check before saving. Click Save. If anything is wrong, Back returns you to the step to fix it.

23.4.5 The same thing through the API

Underneath, a connector is a small record. The documentation's sample script for a database connector posts connectorName, databaseType (for example ORACLE), environmentId, host, port, schemaName, sid, username and password to the engine's /database-connectors endpoint. Notice environmentId: a connector always belongs to one environment. From docs

23.5 File and mainframe connectors

File connectors are created with the same wizard, but the credential step asks for different things. The Source Type is a file format (for example "File - Delimited"), and then you choose a Connection Mode. The list in the documentation is: Filesystem Mount Point, SFTP, FTP, FTPS (only for mainframe data sets), AWS S3, Other S3 Compatible Storage and Azure Blob Storage. The screenshot below shows that dropdown. Details of each mode live on separate pages (the S3, Azure Blob and remote mount pages), which I did not read in full. The file masking chapter picks this up. From docs

For SFTP, FTP and FTPS the credential step asks for the following. The screenshots show the SFTP version.

  • Path: the directory where the files are.
  • Server Name and Port: where the file server listens (22 in the screenshot, the usual SFTP port).
  • User Name and Password (not needed with public key authentication).
  • Public Key Authentication: optional, SFTP only, chosen from the authentication-type dropdown; the page points to a knowledge-base article for the steps.
  • User Directory as root: since version 6.0.9.0, tick this when the Path is relative to the user's home directory on the SFTP server. In the API this flag is userDirIsRoot.
On-the-fly file masking needs two connectors

The connector page explains that for on-the-fly file masking you create a separate environment and connector for the source files. The masked files land in the directory the target connector points at, and the target rule set's file path must point to an existing file there: it does not have to be a copy, just an entry with the same name, which will be replaced. Mainframe data sets are covered by their own connector page: they must be EBCDIC encoded.

Two limits from the page worth knowing: FTP and FTPS are disabled in containerized deployments, and S3 role-based connectivity works only for engines hosted on AWS EC2. Supported file formats for the Files connector are Fixed Width, Delimited, XML, JSON and Parquet (ASCII or UTF-8; Parquet UTF-8).

23.6 Testing, editing and deleting a connector

23.6.1 Testing

Test a connector as soon as you create it. From docs You can do it in two places: with the Test Connection button inside the wizard at any step, and with Test Connection in the connector's Actions (...) menu on the grid. The engine takes the information on the screen, tries to open a database connection, and shows a success or failure message.

Why a failed test is useful information

A failure tells you which layer to blame. Wrong password, wrong schema or wrong database name usually return a login or "not found" message. A hang or timeout points at the network: a firewall, or a port that is not reachable from the engine (the overview chapter lists the ports). A "driver" message points at an unsupported version or a missing JDBC driver. The documentation tells you only that a message shows "success or failure", so these interpretations are my general experience, not from the docs.

23.6.2 Editing

  1. Open the connector's edit wizard.

    Click the connector name, or choose Edit in its Actions menu.

    The same wizard titled "Edit Connection", with values filled in.

  2. Change what you need across the steps.

    To change the password, tick Change Password (the stored password is never shown). To change or replace properties, use Choose File on the Custom Properties step.

  3. Click Save, or review the Summary and then Save.

23.6.3 Deleting

Choose Delete in the Actions menu, then Confirm. Remember: deleting a connector also deletes the rule sets and inventory data that depend on it.
