Chapter 5 explained why a team would shrink a production database before using it for testing. Chapter 12 showed how to find the tables, keys and sensitive columns in a source. This chapter is where you actually build the smaller copy in Informatica Test Data Management (TDM). A data subset is a small slice of production data that still hangs together: if you keep a customer, you also keep that customer's orders and the order lines inside them.

Why do you care? A full copy of production is slow to load, expensive to store and full of real people's data. A random sample of rows is cheap but useless, because a sampled order may point to a customer that was not sampled. A subset gives you the middle path: small and consistent. In the syllabus this is Day 44 ("types of subset, driver tables") and the subset half of the hands-on exercise TDM_Handson3 (data profiling and subset).

13.1 Words to know first

Data subset
A small, targeted copy of production data that keeps related rows together, so it can be used in development, test or training.
Referential integrity
The rule that every foreign key points at a row that exists. An order whose customer is missing breaks it.
Entity
In TDM, a set of tables that are related by physical or logical constraints, built around one starting table. You filter the entity to say "which customers".
Driving table
The one table you pick as the starting point of an entity. The guide says "driving table"; the syllabus says "driver table". They mean the same thing. People also say "root table", but the guide does not use that word.
Group
A set of tables that are not related to each other (or that you want copied without filtering), added to a plan as they are.
Residual table
A table that is not yet in any group or entity. You can sweep these into a group so the target has every table.
Template
An optional container that holds entities and groups. The guide mentions it but gives almost no detail (see 13.5).
Constraint
A rule linking two tables, usually a foreign key from a child table to a parent table. It can be physical (declared in the database) or logical (added in TDM because the database does not declare it).
Major / minor constraint
A severity setting on a foreign key. Major moves in both directions (child to parent and parent to child). Minor moves only child to parent.
Criteria parameter
A named placeholder (for example $$CRITERIAVALUE) used in an entity filter so the value can change at run time without editing the entity.
Plan / workflow
A plan lists what to do (which entities, groups, rules, connections). A workflow is the runnable job TDM generates from the plan.
Staging connection
A database connection TDM uses for temporary working tables, needed for cyclic relationships and some integrity options.

13.2 What a data subset is, and what TDM can subset

The idea in one example

Imagine ShopSphere's production database holds 2 million customers. Your QA team needs a test environment that holds about 10 percent of them, with every order and order line for those customers, and the products those lines refer to. Nothing else. If you did this by hand you would write SQL joins for each table and hope you did not miss a foreign key. TDM lets you describe the shape once (an entity) and the filter once (criteria), then repeats it on demand.

Why it matters

Smaller data loads faster and costs less to store. Because the subset is referentially intact, the application under test does not crash on "customer not found" errors that have nothing to do with the feature being tested. And because you can combine subsetting with masking in the same plan, the small copy can also be safe to hand out (chapter 14).

What the guide says From docs

  • You create a subset when you need "a small, targeted, and referentially intact copy" of production data for a non-production environment such as development, test or training. The guide's own example is financial data for one region or one time period (User Guide 10.5.10, p.112).
  • Sources can be relational databases, flat files or XSD (XML structure) files (p.112).
  • You define data subset components and add them to a plan. You then generate a workflow from the plan, and the workflow loads the subset into a target database (p.112).

Three kinds of source means three slightly different ways of working. Relational and flat file sources use entities and groups. XSD sources use criteria on elements and attributes instead. Most of this chapter is about the relational case, because that is what ShopSphere uses and what beginners meet first. XSD gets its own short section (13.8).

The guide lists five kinds of task you can do around data subset in Test Data Manager (User Guide 10.5.10, p.113) From docs:

Create criteria parameters
Parameters used inside entity filters. They let you run the same workflow for different values without touching the entity, plan or workflow. Global parameters work across projects; you can import one into a project first or use it from the global level.
Create subset components
Entities (with filter criteria) and groups.
Edit subset components
Change entities and groups you created or imported. You can optimize relations in the entity, or leave that to run time.
Export or import components
Move entities and groups to a different Test Data Manager Service as files.
Run a plan
Add relational, flat file or XSD sources to a plan with the components and criteria, then run it.

The guide's summary of an entity is worth memorising: you create it "when you need to copy data from related tables", you can build it by hand or reuse one that came from profile results (the data discovery you did in chapter 12), and TDM stores it in the project (p.113).

Analogy, and where it stops

Think of an entity as a family tree you pull from one person: you pick one person (the driving table), and everyone linked to them comes along. A group is a box of loose papers you toss in without checking who is related. The analogy stops being accurate at "everyone comes along": TDM follows constraints and then applies major or minor rules and integrity options (13.6) to decide how far it goes.
