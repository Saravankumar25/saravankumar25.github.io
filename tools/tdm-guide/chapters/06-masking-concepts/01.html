6.1 Words to know first

Masking
Replacing sensitive values with realistic but fictitious values so test data cannot identify real people. Delphix defines it as iterating through a dataset to identify all sensitive fields and replace them with desensitised values to eliminate risk in lower environments.
Technique (Informatica) / algorithm (Delphix)
The method that changes a value, such as substitution or date shift. Informatica turns a technique plus settings into a rule. Delphix turns an algorithm framework plus settings into an algorithm instance.
Deterministic
Always gives the same output for the same input (and same settings). The opposite is non-deterministic or random: a different output each time.
Repeatable
Informatica's word for deterministic output across runs and tables, switched on with a seed.
Seed / key
A starting value that controls the output of a deterministic technique. Same seed (Informatica) or same algorithm key (Delphix) gives the same masked values; changing it changes them.
Dictionary / lookup file
A list of replacement values, such as thousands of first names, that substitution picks from.
Collision
Two different inputs masked to the same output. Fine for names, harmful for a column that must be unique.
Irreversible
You cannot get the original value back from the masked one.
Format-preserving
The masked value keeps the original's shape: a 10-digit phone stays 10 digits, a card number keeps its checksum.
In-place and on-the-fly
In-place masking changes the data where it sits. On-the-fly masking reads unmasked data and writes masked data to a different place.

How the sources use the words: From docs

  • Delphix says tokenization is "the only type of algorithm that allows you to reverse its masking". Its example is masking data before sending it to a vendor and reversing it afterwards to act on the vendor's findings (terminology page). Its introduction labels masking as anonymisation and tokenization as pseudonymisation. It also says unlike encryption, which can be bypassed by obtaining user credentials, masking irreversibly protects data in downstream environments, and that encryption is ill-suited to protecting non-production environments (Delphix "Introduction to Delphix Masking").
  • Informatica treats encryption as one masking technique. Standard encryption offers AES, CRC and MD5, and format preserving encryption can be decrypted with the same pass phrase and configuration (User Guide 10.5.10, p.161).
  • GenRocket argues that traditional masking "can be reverse engineered" and that its Synthetic Data Replacement generates new values that cannot be traced back (GenRocket "G-Subset Overview" and "What is Synthetic Data Replacement").
Reversible is a risk in test data

If a test copy can be turned back into the real data, then stealing the copy plus the key or mapping table is a breach. For ordinary test environments, prefer irreversible masking. Use encryption or tokenization when you truly need to come back, such as a vendor round trip, and guard the key like production data.

Anonymisation is a destination, masking is a vehicle

Masking is a set of techniques. Whether the masked result counts as anonymous under a law depends on the whole data set (the combinations you saw in the sensitive data chapter) and is the compliance officer's call.

6.3 What good masked data looks like

A tool could blank every sensitive column in a second. That would be safe and useless. Masking has competing goals, and good masking meets all of them.

The goals of masking
GoalMeaningWhat goes wrong without it
SafeReal values cannot be recovered or inferredA leak of test data is a leak of customers
RealisticLooks like real data: names look like names, emails like emailsTesters cannot spot UI bugs, and validation rules reject the data
ValidPasses the application's rules: format, checksum, length, rangesThe card form refuses every masked card number
ConsistentThe same real value maps to the same fake value everywhere it appearsJoins break; a customer has different names in two tables
RepeatableA re-run gives the same results when it shouldTest cases that rely on a specific customer fail after each refresh
Fit for purposeKeeps the properties the tests depend on (a customer has several orders, a date precedes another)The data is fake but the test no longer tests anything

From docs Both vendors state these goals. Informatica: replace source data in sensitive columns with "realistic test data" for nonproduction environments (p.135). Delphix: the data stays "production-like in quality", masking is consistent while "maintaining referential integrity across heterogeneous data sources", and it is irreversible (Delphix "Introduction to Delphix Masking").

Some goals pull against each other. Perfect safety says "change everything completely". Perfect fidelity says "keep it as it was". Every technique in the next section is a compromise somewhere between those poles, which is why choosing is a skill.
