Substitution

Replace the value with a different, believable one picked from a list. Informatica: it "replaces a column of data with similar but unrelated data from a dictionary", which can be a flat file or a database table (p.176). Delphix Secure Lookup is the same idea: it picks a replacement from a lookup file using a cryptographic hash of the original value, so the output is consistent for each input (terminology page; the framework page says the default hash method is SHA256). Strengths: very realistic. Limits: the list can run out. Informatica's unique substitution makes the operation fail when the source has more distinct values than the dictionary has (p.176), and Delphix says that two inputs can collide on one output, which is fine for names and a problem for unique columns (terminology page). Informatica also lets you pick names by a lookup column such as gender or country, so female names stay female (pp.177 to 179).

Shuffle

Move the existing values of a column between rows. Informatica's own example moves first names between four rows: Tom, Sue, Bob, Eli become Bob, Eli, Tom, Sue (p.173). Delphix SecureShuffle guarantees that each value moves to a different row, but an input can still mask to itself when values repeat (SecureShuffle page). From docs

The catch: the values are still real. Someone who knows Asha Menon's first name and city could still recognise "Menon" in the column, and a rare value stays rare. Delphix warns that shuffling does not redact or modify any value, so consider carefully whether it meets your security requirements. Informatica offers a constrained shuffle (for example, only within the same city) and a representative shuffle, in which all rows with the same source value get the same shuffled value (p.174).

Key masking

Produce a deterministic masked value from the input and a seed: same input, same seed, same output. Informatica's Key technique works for dates, numbers and strings, and you can limit each output character to letters, digits or alphanumerics with a mask format (pp.164 to 168). For numbers, the guide says to use the same seed in the primary key column and the foreign key column so referential integrity is maintained (p.167). From docs Delphix does the same job with Character Mapping, which maps each value to another value built from the same character groups, giving no two inputs the same output, which suits primary and foreign key columns (Character Mapping page).

Encryption and tokenization

Informatica offers standard encryption (AES, CRC, MD5, with a key of 16 characters or fewer) and format preserving encryption. The latter can keep the format and length, and can be decrypted with the same pass phrase and configuration. Its example: Abc123@xyz.com becomes Mpz849#dje!kuw, or Mpz849@dje.kuw if the "@" and "." are excluded from encryption (pp.161 to 162). The Delphix Tokenization framework uses AES-128 and produces longer alphanumeric tokens, built for the vendor round trip described in 6.2 (Tokenization page). From docs Because AES and format preserving encryption can be reversed, use them only when reversal is the goal.

Nulling and redaction

Remove the value, or part of it. Informatica's Nullification replaces a column with NULL, works on all data types and has no parameters (p.168). From docs The simplest safe answer for a column the tests do not use, such as tax_id, is NULL. The cost: NOT NULL columns refuse it and the application paths that read the column go untested. Free text needs smarter redaction: Delphix's Free Text Redaction finds sensitive words and patterns inside a text column (for example "St", "Blvd", or the shape 123-45-6789 for an SSN) and redacts the whole matched word, but it "requires some expertise to use" (Free Text Redaction page). From docs

Date shifting and blurring

Move a date by an amount so that the exact date is hidden but the date still looks plausible. Delphix Date Shift masks each date to another within a configured range (for example 3 to 5 days later), based on the algorithm key; a fixed shift (same minimum and maximum) preserves uniqueness and referential integrity, unlike variable ranges. Its docs show 2021-02-03 12:30:00 becoming 2021-02-06 12:30:00 (Date Shift page). Informatica blurs a date within a range of years, months, days or hours: a source of 2 February 2006 with a two-year bound becomes a date between 2 February 2004 and 2 February 2008 (p.170). Numeric variance

Move a number by a controlled amount. Informatica numeric blurring uses a fixed or percent variance. With the input 66: fixed bounds 10 and 10 give a result between 56 and 76; percent bounds 50 and 50 give 33 to 99 (p.170). A range option returns a number between a minimum and a maximum. Delphix Min Max pulls extreme values toward the middle, because a record with the highest salary may reveal a company's CEO (Min Max Number page). From docs On ShopSphere, a 10 percent blur turns total_amount 1200.00 into something between 1080.00 and 1320.00, which keeps totals plausible but breaks the rule "total equals the sum of its items" unless the items are changed too, so decide whether tests rely on that.

Format-preserving masking

The masked value keeps the format the application checks. Informatica has built-in formats. Credit card masking returns a number with a valid checksum, leaves the six-digit bank identification number unchanged, and can keep or change the card issuer: 4539 1596 8210 2773 becomes 4539 1516 0556 7067 (p.158). Phone masking keeps the format: (408)382 0658 becomes (408)256 3106 (p.169). SSN masking generates valid numbers that avoid ones the Social Security Administration has issued (p.175). Delphix Payment Card preserves the Luhn check and the leading digits you choose: 5419033646326699 becomes 5419036803270758 when the first six digits are kept (Payment Card page). From docs

Character replacement

Replace characters according to a pattern. In Informatica's key and random techniques you set a mask format: A for letters, D for digits, N for alphanumerics, X for any character, + for "leave as is", and R for the remaining characters (pp.165, 170); and you can mask only chosen source characters or restrict the result to chosen characters. Delphix's Character Replacement framework swaps listed characters (for example vowels to "+") and wraps another string algorithm, and the page notes it has no UI or default instance at present, so it is configured through the API. From docs A ShopSphere use: a tax ID shaped like AKPPM4821Q (five letters, four digits, one letter) masked with format AAAAADDDDA becomes something like TRWQD9037B, same shape, no real content.

Algorithm chaining

Combine several steps into one result. Informatica's advanced masking uses input, variable and output columns: mask FIRST_NAME and LAST_NAME separately with substitution into variable columns, then output FIRST_MASKED || ' ' || LAST_MASKED as the full name (p.158). Its email masking can build the address from the masked first and last name (p.159). Delphix's String Algorithm Chain runs two to eight string algorithms one after another, and its docs give a reason to chain: with deterministic masking, a very rare input value keeps its low frequency in the output and could be used to infer the original, so a first algorithm can alter such rare values before the main one runs (String Algorithm Chain page). From docs

Why chain at all?

Real columns are related: the email contains the name, the full name contains the first name. If each is masked independently, the masked email will name someone different from the masked name. Chaining makes the dependent value follow the one it depends on.
