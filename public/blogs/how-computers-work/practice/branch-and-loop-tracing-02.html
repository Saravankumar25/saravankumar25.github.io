Branch and loop tracing

Set 2 of 4 · 32 worked questions. Predict your result before expanding the solution.

These worked traces are meant to build fluency through controlled variation. If several answers feel identical, try the next difficult value and look for the point where a carry, sign, branch, or selected memory address changes the outcome.

Program execution · Problem 0033

Start a counter at 100; subtract 1 each iteration while it remains >0. How many iterations?

Try it on paper first. The worked answer is hidden below.

Reveal detailed solution →
  1. The program starts with an accumulator/counter containing 100.
  2. One loop iteration subtracts 1 from the counter.
  3. A conditional branch repeats the body only while the counter is greater than zero.
  4. After one iteration the counter is 99.
  5. After two iterations the counter is 98.
  6. In general, after k iterations the counter is 100 − 1×k.
  7. The loop first stops when k≥100/1.
  8. The smallest whole-number iteration count meeting that requirement is 100.
  9. The final counter equals 100−100×1=0.
  10. The next PC must take the fall-through route instead of the repeat branch.
  11. This example uses a greater-than-zero condition; branch-on-not-equal would have different termination behavior for some step sizes.

Final answer: 100 iterations

Try it on paper first. The worked answer is hidden below.

Reveal detailed solution →
  1. The program starts with an accumulator/counter containing 190.
  2. One loop iteration subtracts 1 from the counter.
  3. A conditional branch repeats the body only while the counter is greater than zero.
  4. After one iteration the counter is 189.
  5. After two iterations the counter is 188.
  6. In general, after k iterations the counter is 190 − 1×k.
  7. The loop first stops when k≥190/1.
  8. The smallest whole-number iteration count meeting that requirement is 190.
  9. The final counter equals 190−190×1=0.
  10. The next PC must take the fall-through route instead of the repeat branch.
  11. This example uses a greater-than-zero condition; branch-on-not-equal would have different termination behavior for some step sizes.

Final answer: 190 iterations
