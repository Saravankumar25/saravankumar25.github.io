72 questions answered

A plain-language answer to the central question from every lesson, with the most common misconception immediately underneath.

Question 01

Why can a machine follow instructions?

A computer is a collection of parts that change and store physical states according to rules. Pressing a keyboard key eventually changes electrical signals, which a processor interprets under a programmed convention.

Careful: A CPU is not a small person making decisions; it is a physical system whose wiring implements decisions.

Question 02

How does electricity become a bit?

A wire carries a changing voltage, and a receiving circuit interprets a voltage range as low or high. Suppose LOW covers approximately 0–0.8 V and HIGH covers approximately 2–3.3 V in an illustrative system; the uncertain middle must be avoided.

Careful: Zero does not necessarily mean absolutely no electricity, and one does not necessarily mean a fixed voltage everywhere.

Read the full explanation →
Question 03

Why only two states?

Real signals fluctuate; separating two valid regions leaves room for imperfections. A sender outputs an acceptable high voltage; a receiver distinguishes it from low despite modest voltage loss.

Careful: Binary is not mathematically the only possible electronic design; it is a particularly practical engineering choice.

Read the full explanation →
Question 04

What makes a circuit controllable?

A transistor can use one electrical signal to regulate another, enabling enormous networks of on/off behavior. A CMOS inverter pairs transistors so that a high input tends to produce a low output and vice versa.

Careful: A transistor is not simply a mechanical light switch; real devices have thresholds, leakage, delay, and analog behavior.

Read the full explanation →
Question 05

When does a bit become information?

A bit distinguishes two states; a convention assigns meaning to patterns of bits. 01000001 may be 65 as an unsigned number or the letter A under ASCII; the stored pattern did not change.

Careful: Bits do not carry built-in labels saying number, text, or instruction.

Read the full explanation →
Question 06

How can trillions of tiny events seem simple?

Engineers build layers: physical devices, gates, circuits, processor, instructions, software, applications. A language instruction to add numbers becomes operations that trigger register reads and a physical adder.

Careful: No one layer explains the entire machine; each is a useful model with carefully chosen omissions.

Read the full explanation →
Question 07

Why is 724 equal to 724?

Each decimal digit has a positional weight: ones, tens, hundreds and so on. 724 = 7×100 + 2×10 + 4×1; the positions correspond to 10², 10¹ and 10⁰.

Careful: The symbol 724 is a representation of the quantity, not the quantity itself.

Read the full explanation →
Question 08

What changes when the base is two?

The positions weigh 1, 2, 4, 8, 16, 32 and continue doubling. 1011₂ = 8 + 0 + 2 + 1 = 11₁₀; every zero contributes nothing.

Careful: Binary 10 is not decimal ten; it represents decimal two.

Read the full explanation →
Question 09

How do you read an unfamiliar bit pattern?

Multiply every bit by its power-of-two weight, then sum only the active weights. 11010₂ = 16 + 8 + 2 = 26₁₀; the 4 and 1 columns are absent.

Careful: You do not read a binary string as its decimal-looking digits.

Read the full explanation →
Question 10

How do you write 45 with only 0 and 1?

Repeatedly subtract the largest fitting power of two, or repeatedly divide by two and collect remainders. 45 = 32 + 8 + 4 + 1, so its bit pattern is 101101₂.

Careful: Leading zeros usually do not change unsigned value, but fixed-width storage still includes them.

Read the full explanation →
Question 11

Why does bit width matter?

With n independent bits there are 2ⁿ patterns; their interpretation determines what range they represent. Unsigned 8-bit patterns represent 0 through 255; unsigned 4-bit patterns represent 0 through 15.

Careful: A 64-bit processor does not force every number or every instruction to have exactly 64 bits.

Read the full explanation →
Question 12

Why do engineers use A–F?

Hexadecimal groups four binary digits into one symbol from 0–9 or A–F. 1101 1010₂ becomes DA₁₆ because 1101=13=D and 1010=10=A.

Careful: Hexadecimal is not a different electrical encoding; it is a compact written notation for the same bits.

Read the full explanation →
Question 13

How can 1+1 produce 10?

A binary digit holds only zero or one; exceeding one produces a carry to the next column. 0011₂ + 0001₂ = 0100₂; two trailing ones trigger consecutive carries.

Careful: Binary addition uses the same place-value principle as familiar decimal addition.

Read the full explanation →
Question 14

What if two operands and a carry meet?

The sum of three single bits can be 0, 1, 2 or 3; output is the low bit and carry is the high bit. 1 + 1 + 1 = 3 = 11₂, therefore SUM=1 and CARRY=1.

Careful: The carry is not an error or an extra digit in the same column.

Read the full explanation →
Question 15

How can a bit pattern mean negative five?

In n-bit two’s complement, the leading position has weight −2ⁿ⁻¹ and the other positions remain positive. 1011₂ at 4 bits is −8 + 2 + 1 = −5; 0111₂ is +7.

Careful: Two’s complement requires a known bit width; 1011₂ alone has no inherent sign.

Read the full explanation →
Question 16

Why flip bits and add one?

For fixed-width n-bit arithmetic, the bitwise complement plus one equals the additive inverse modulo 2ⁿ. At 8 bits, 00000101 → 11111010 → 11111011, which represents −5.

Careful: The most-negative signed number cannot be negated within the same width without overflow.

Read the full explanation →
Question 17

Why does one adder do both jobs?

A − B is computed as A + (NOT B) + 1 using the same fixed-width binary adder. 6 − 2 at four bits becomes 0110 + 1101 + 1 = 0100 after discarding the fifth carry.

Careful: Discarding the carry works for modular fixed-width arithmetic; interpreting overflow needs care.

Read the full explanation →
Question 18

When can correct circuitry produce the wrong answer?

A finite register wraps modulo 2ⁿ; signed overflow occurs when a mathematical result exceeds its signed range. 0111 + 0001 = 1000 at four bits: true arithmetic gives +8, but 1000 represents −8 as signed.

Careful: Carry-out and signed overflow are different conditions; they cannot be used interchangeably.

Read the full explanation →
Question 19

Can a complete behavior fit in four rows?

A truth table lists every input combination and the corresponding output. Two inputs A and B yield 00, 01, 10 and 11; a gate specifies its output for each row.

Careful: A truth table describes behavior but does not tell you the transistor implementation.

Read the full explanation →
Question 20

When must conditions agree?

AND produces one only when every input is one; OR produces one when at least one input is one. For A=1 and B=0, AND=0 while OR=1.

Careful: Digital OR is inclusive: two true inputs still produce true.

Read the full explanation →
Question 21

Why is inversion so powerful?

NOT reverses a bit; NAND and NOR invert AND and OR results. NAND(1,1)=0 while NAND(1,0)=1; NOR(0,0)=1 and zero otherwise.

Careful: NAND and NOR are universal for Boolean logic, but universal does not mean optimal for every design.

Read the full explanation →
Question 22

Which gate detects differences?

XOR outputs one when its inputs differ; XNOR outputs one when they match. XOR(1,0)=1, XOR(1,1)=0; it is the single-bit sum without a carry.

Careful: XOR is not the same as OR when both inputs equal one.

Read the full explanation →
Question 23

How does a computer choose one value?

A 2-to-1 multiplexer outputs A when select is zero and B when select is one. Y=(NOT S AND A) OR (S AND B), which implements a selector with basic gates.

Careful: The select signal does not mathematically add its inputs; it decides which input is forwarded.

Read the full explanation →
Question 24

How can two address bits pick one of four places?

A decoder asserts a distinct output for each input code, often conditioned on enable. Input 10₂ to a 2-to-4 decoder activates output line 2 and leaves others inactive.

Careful: A decoder is not necessarily the reverse of an encoder under all validity and enable conditions.

Read the full explanation →
Question 25

Can two gates add two bits?

A half adder uses XOR for sum and AND for carry-out. A=1,B=1 gives SUM=0 and CARRY=1, describing the binary answer 10₂.

Careful: A half adder has no carry-in, so it cannot correctly handle every column of multi-bit addition.

Read the full explanation →
Question 26

What was the missing input?

A full adder combines A, B and carry-in, producing sum and carry-out. Two half adders plus an OR gate can implement S=A XOR B XOR Cin and Cout=AB + Cin(A XOR B).

Careful: A full adder is a combinational circuit; it does not itself remember the previous carry.

Read the full explanation →
Question 27

How do eight bits cooperate?

Connect each stage’s carry-out to the next stage’s carry-in. For 01111111+00000001, the carry ripples through seven columns to produce 10000000.

Careful: The sum may take longer to settle when a carry crosses several stages.

Read the full explanation →
Question 28

How can the same gates subtract?

Route each B bit through XOR with a SUB control and make that control the first carry-in. When SUB=0, B passes unchanged and Cin=0; when SUB=1, B is inverted and Cin=1.

Careful: One shared circuit saves hardware but does not remove all instruction decode and flag logic.

Read the full explanation →
Question 29

How does a processor choose ADD or AND?

An ALU computes arithmetic and bitwise results and selects an output using operation control bits. An 8-bit ALU might support ADD, SUB, AND, OR, XOR and pass-through operations.

Careful: ALU is not a complete CPU; it lacks instruction sequencing, memory and storage.

Read the full explanation →
Question 30

How can later instructions know what happened?

Extra circuit outputs can report zero, negative, carry and signed overflow status. Subtracting 7 from 7 returns zero and raises a zero flag that a branch may test.

Careful: The precise flag behavior depends on the chosen ISA and instruction; do not generalize to every chip.

Read the full explanation →
Question 31

What changes when a circuit remembers?

Combinational output depends on current inputs; sequential output also depends on stored state. AND follows its inputs immediately after propagation delay; a latch can retain the last stored state.

Careful: Storage always relies on physical state; a label named memory does not cause retention.

Read the full explanation →
Question 32

Can logic gates sustain a state?

Cross-coupled gates feed back into one another, allowing two stable logic conditions. A basic SR latch uses coupled NOR or NAND gates; setting and resetting drive it into a desired state.

Careful: Certain simultaneous set/reset combinations are invalid or problematic for a basic SR latch.

Read the full explanation →
Question 33

How do we avoid ambiguous set/reset controls?

A D latch presents one data input and an enable that decides whether data is copied or retained. With enable=1, Q tracks D after delays; with enable=0, Q holds its previous value.

Careful: A level-sensitive latch is not the same as an edge-triggered flip-flop.

Read the full explanation →
Question 34

How does a clock create orderly updates?

An edge-triggered D flip-flop captures input at a chosen clock transition and holds the result. D is sampled on a rising edge, Q changes shortly afterward, and the previous Q remains until the next edge.

Careful: Real flip-flops require setup and hold timing; a clock edge is not magic instantaneous computation.

Read the full explanation →
Question 35

How can a circuit remember a whole number?

Place several flip-flops side by side under a shared clock and load-enable control. An 8-bit register captures 8 separate inputs on the same active edge.

Careful: A register is not necessarily the same physical structure as a large RAM array.

Read the full explanation →
Question 36

How does hardware keep track of a step number?

Feed a register output through an incrementer and load the incremented value on each clock edge. At 4 bits, 1110 → 1111 → 0000 when repeatedly incremented; the counter wraps.

Careful: Clock frequency does not mean every instruction finishes in exactly one cycle.

Read the full explanation →
Question 37

What happens after the ALU finishes?

A computed result must be retained somewhere so a later operation can reuse it. Compute 2+3, store 5, later multiply or add another value using that stored result.

Careful: A fast ALU does not provide useful multi-step computation without accessible state.

Read the full explanation →
Question 38

How do you choose a storage location?

An address selects a memory location; a data value is the bit pattern stored there. A four-bit address can label 16 slots, indexed 0–15; each slot might hold eight data bits.

Careful: Memory size depends on addressable slots and bits per slot; do not confuse addresses with data values.

Read the full explanation →
Question 39

How are stored bytes changed?

A write selects a location and supplies new data; a read selects a location and receives existing data. WRITE address 3 ← 10101010, then READ address 3 → 10101010.

Careful: Real RAM technologies differ in timing and internal construction; this is a logical interface model.

Read the full explanation →
Question 40

Can gates build a memory array?

Use storage cells, row selection and output selection logic to construct a simple register-file-like memory. A 2-bit row select chooses one of four stored words; multiplexers route the selected word outward.

Careful: Typical DRAM does not physically build every bit from ordinary flip-flops; it uses charge-storage cells.

Read the full explanation →
Question 41

Can a circuit output stored patterns without writes?

ROM holds predefined data or control patterns, indexed by address. A 4-bit address can select one of 16 constant bytes; a seven-segment decoder can use this approach.

Careful: ROM refers to a read-only interface in this model; modern nonvolatile memories may have reprogramming mechanisms.

Read the full explanation →
Question 42

How can several parts exchange one word?

A bus is a coordinated group of signal lines, often with selection, direction and control rules. Registers, ALU and RAM can exchange bytes over an 8-bit data path under control signals.

Careful: Real bus architectures range far beyond a single shared wire bundle; modern systems often use complex interconnects.

Read the full explanation →
Question 43

Where does a CPU keep the current answer?

A simple accumulator CPU uses one main register as a frequent ALU source and destination. LOAD 5, ADD 3, STORE 8 can be implemented by moving values through an accumulator.

Careful: This educational design is not representative of every modern register-rich CPU.

Read the full explanation →
Question 44

Why keep several values close to the ALU?

Registers provide fast, small storage directly managed by instructions. Register R1 can hold a loop counter while R2 holds a running sum.

Careful: A register file is not interchangeable with a CPU cache even though both store data.

Read the full explanation →
Question 45

How does a CPU hold its current command?

An instruction register captures the instruction bits being decoded and executed. The fetched byte 00100011 is latched into IR, then its fields help select sources and operation.

Careful: An instruction register is a design concept; real CPUs can hold many instructions in pipeline stages.

Read the full explanation →
Question 46

How does a computer know the next instruction?

PC stores the address of the next instruction to fetch, subject to branching. PC=6 fetches a byte; a one-byte sequential instruction would normally make PC=7.

Careful: PC increments by instruction size, not universally by one, on real processors.

Read the full explanation →
Question 47

What repeats while code runs?

Fetch gets instruction bits, decode chooses a behavior, execute changes registers, memory or PC. LOAD takes memory data into a register; ADD uses the ALU; JUMP changes the next fetch address.

Careful: Execution often has extra memory, writeback and pipeline steps; three words are a teaching summary.

Read the full explanation →
Question 48

Who moves the data and who decides when?

The datapath performs operations and carries values; control drives selectors, loads and enables. A LOAD instruction asserts the right RAM select, bus source and register load signal in order.

Careful: Control is not necessarily implemented with one physical central box in every CPU.

Read the full explanation →
Question 49

How can a byte command a processor?

Reserve some instruction bits for opcode and others for register IDs or immediate values. With a four-bit opcode and four-bit operand, there are 16 opcode patterns and 16 operand patterns.

Careful: Opcode format is an architectural choice; there is no one universal bit layout.

Read the full explanation →
Question 50

What is a contract between code and hardware?

An ISA specifies programmer-visible instructions, registers, behavior and relevant memory rules. Two different processors can execute the same ISA yet use different internal circuits.

Careful: Architecture and microarchitecture are not synonyms.

Read the full explanation →
Question 51

How does a decoded opcode operate wires?

Control logic turns instruction fields and timing state into load, enable, select and write signals. A STORE may assert address selection, output enable from a register, then RAM write-enable.

Careful: The ALU output alone cannot guarantee data is stored; a destination load event is also needed.

Read the full explanation →
Question 52

Can a table orchestrate the CPU?

A control ROM maps an instruction and microstep to a word of control bits. At fetch step T0 enable PC address; at T1 load IR and advance PC; at T2 execute opcode-dependent action.

Careful: Not every CPU is microcoded; hardwired control is another valid option.

Read the full explanation →
Question 53

Why does operation order matter?

Propagation, setup/hold, and shared resource conflicts determine when values can safely be captured. Set RAM address before expecting valid data; enable a receiving register only when the data is stable.

Careful: A circuit drawn logically correctly can still fail if clock and combinational delays are ignored.

Read the full explanation →
Question 54

How does code make an if-statement?

A branch instruction tests status information and selects either sequential or target PC. SUB R1,R2 sets Z=1 if equal; BEQ label changes PC only when that zero flag is set.

Careful: Some instruction sets compare without storing a subtraction result, and flags vary by architecture.

Read the full explanation →
Question 55

How do human-readable instructions become bytes?

Assembly uses readable mnemonics that an assembler encodes into machine instructions. LDA 3 might encode as opcode 0001 and address 0011 in a designed toy ISA.

Careful: Assembly syntax and instruction encoding are not portable across different ISAs.

Read the full explanation →
Question 56

Can a few instructions produce a visible result?

A program is an ordered collection of operations that move and transform state. LOAD #5; ADD #7; OUT; HALT makes the accumulator become twelve before output.

Careful: The meaning of the # symbol depends on a chosen toy assembly convention; it commonly marks an immediate.

Read the full explanation →
Question 57

Why does one instruction run many times?

A branch can move PC to an earlier address; a condition decides when to stop repeating. Set a counter to five, decrement once each loop, branch while it is nonzero.

Careful: A loop without a reachable exit condition can run indefinitely.

Read the full explanation →
Question 58

How does a simple CPU calculate a sequence?

Keep two consecutive values; output one and replace the pair with old-second and their sum. Start a=0,b=1: output 0,1,1,2,3,5,8,13; update (a,b)←(b,a+b).

Careful: At eight bits, unsigned Fibonacci terms eventually exceed 255 and wrap without larger arithmetic.

Read the full explanation →
Question 59

How do you debug a program without guessing?

Record register, bus, PC, control state and memory values after important steps. For LOAD 4, observe PC fetch, IR load, effective memory address and accumulator update.

Careful: A final correct output does not prove every intermediate timing or state transition was correct.

Read the full explanation →
Question 60

What part is programmable?

Instructions express allowed behaviors; underlying hardware implements those behaviors. An unsupported multiplication may be implemented through repeated additions if the ISA permits loops.

Careful: Software flexibility always rests on a hardware instruction contract.

Read the full explanation →

Was a real smartphone fundamentally different?

The original 2007 iPhone used a Samsung S5L8900 system-on-chip with an ARM11-class ARM1176JZF-S core. Its ARMv6-compatible processor used a rich register set, cache and memory subsystem rather than a tiny accumulator datapath.

Careful: The simple CPU is a pedagogical model, not a transistor-level recreation of that commercial SoC.

Question 62

What makes assembly on ARM more expressive?

ARM-style instructions can name multiple registers, perform operations and access memory with explicit conventions. In ARM syntax, ADD r0, r1, r2 conceptually computes r0←r1+r2; the instruction’s exact form depends on execution state.

Careful: Instruction formats, privilege levels and register banking complicate the real machine beyond the toy design.

Read the full explanation →
Question 63

Why are RAM operations distinct?

In a typical ARM load/store design, arithmetic operates on registers while dedicated load/store instructions access memory. LDR r0,[r1] reads from the address in r1; STR r0,[r1] writes to that address in a suitable context.

Careful: The square brackets express address dereference; r1 and the value stored at address r1 are different.

Read the full explanation →
Question 64

Why do machine-code tools display 0x?

Engineers view binary in hexadecimal because each hex digit corresponds exactly to four bits. 0xE3A00001 is eight hex digits, representing 32 bits; its interpretation depends on the architecture and state.

Careful: Not every hex string is an instruction, and endianness changes byte order in memory displays.

Read the full explanation →
Question 65

How can code control an LED?

A processor can control peripheral registers by reading and writing addresses mapped to hardware rather than ordinary RAM. A GPIO controller may expose direction and output registers; writing selected bits changes pin behavior.

Careful: Writing an arbitrary address on a desktop OS will not safely control hardware; exact hardware manual, privilege and mapping are required.

Read the full explanation →
Question 66

Why are real microcontrollers more demanding?

Physical devices have voltage, current, timing, safety and ownership constraints outside pure code. An LED needs an appropriate resistor or current-limited driver; GPIO pins have maximum ratings.

Careful: Never wire an LED directly to an unknown pin or run MMIO code without the specific board documentation.

Read the full explanation →
Question 67

Why can many programs share one machine?

An operating system coordinates process execution, memory, files, devices, permissions and system calls. A scheduler may switch CPU execution between runnable processes and preserve their state.

Careful: Fast alternation on one core is concurrency, not the same as simultaneous execution on multiple cores.

Read the full explanation →
Question 68

What if something urgent happens?

Interrupts and exceptions redirect execution to special handlers while preserving a return path. A timer interrupt can let an OS regain control and consider scheduling another task.

Careful: Interrupt handling depends on privilege and architecture; a simple clock pulse is not itself an interrupt.

Read the full explanation →
Question 69

Why is a CPU faster than RAM?

Fast small storage reduces average access time by keeping likely-needed instructions and data nearby. A cache hit serves a read from a nearby cache line; a miss may fetch from deeper memory.

Careful: A cache is not a magical always-consistent copy; coherence, replacement and write policies matter.

Read the full explanation →
Question 70

Can a CPU overlap instructions?

A pipeline divides instruction handling into stages so different instructions occupy different stages concurrently. One instruction may execute while another decodes and a third fetches, when dependencies permit.

Careful: Pipelines improve throughput but do not make each individual instruction take zero time.

Read the full explanation →
Question 71

How does familiar code turn into machine actions?

Compilers transform higher-level program meaning into lower-level operations and instruction sequences. The expression total=a+b may compile into loads, a register ADD and a store depending on optimization and context.

Careful: One source line is not guaranteed to map to one machine instruction; compilers optimize and rearrange.

Read the full explanation →
Question 72

How do you keep a complete mental model?

A computing system is a stack of representations and contracts, from voltages through bits and gates to software. A click produces device events, operating-system dispatch, application logic, instructions, transistor switching and visible pixels.

Careful: Understanding the bottom does not remove the need to study protocols, compilers, security or distributed systems.
